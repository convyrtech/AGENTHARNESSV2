# План v1: универсальный агентный харнес для казуальных пользователей

Последнее обновление: 2026-10-22. Это рабочий документ: после каждого этапа исследований и экспериментов он уточняется. Подтверждённые факты и открытые гипотезы ведутся в `STATUS.md`.

---

## 1. Продукт и цель

**Что строим.** Десктопное приложение (Tauri 2 + React, Windows/macOS/Linux) с агентом, который работает с локальными файлами, кодом и сервисами пользователя. Внутри — переключаемые профили: «Код», «Повседнев», «Творчество».

**Для кого.** Казуальные пользователи. Они не знают и не хотят знать, как это устроено, не умеют писать промпты и формулировать задачи. Типичный запрос: «сделай пиздато то, не знаю что, не знаю как». Пользователь додумывает по ходу и не собирает референсы заранее.

**Модель бизнеса.** Клиент бесплатный, работает только через ключи нашего сервиса. Сервис перепродаёт модели с маркетплейса a6api (решение владельца: только маркетплейс). Ценность для пользователя:
- дешёвый доступ к моделям без VPN;
- харнес, который выжимает максимум из дешёвых моделей;
- современное и удобное приложение.

**Главное обещание (после исследований):** не «уровень Claude Code на дешёвых моделях», а **«почти тот же результат в разы дешевле, стабильнее и без умения писать промпты»**. Независимые данные показывают, что готовые харнесы почти не различаются по доле решённых задач (±1–2 п.п.), зато сильно различаются по стоимости (до 40×). Дешёвым моделям обвязка помогает сильнее всего (+10–15 п.п.).

## 2. Архитектура (верхний уровень)

```
┌────────────── Десктоп (Tauri 2) ───────────────┐
│ React UI: чат · план простыми словами ·        │
│   превью · дифф · дерево сессий · память ·     │
│   «комната» агентов · стоимость                │
│ Rust-мост: снапшоты файлов, keychain,          │
│   индекс памяти (SQLite FTS5 + sqlite-vec)     │
│ Sidecar: Pi SDK (по образцу Graphone) +        │
│   наши пакеты расширений                       │
└───────────────────────┬────────────────────────┘
                        │ OpenAI-формат
┌───────────────────────▼────────────────────────┐
│ Наш шлюз: авторизация · биллинг · закрепление  │
│ поставщика за сессией · канарейки · рейтинг    │
│ поставщиков · детектор «ответов-ошибок» ·      │
│ вычистка секретов                              │
└───────────────────────┬────────────────────────┘
                        ▼
                a6api (маркетплейс)
```

**Ядро — Pi** (earendil-works/pi, MIT, v1.4): минимальный цикл, виртуальные модели для ролей, расширения, пакеты, дерево сессий.
- DeepSeek обучал V4.1 в том числе на Pi.
- Стоковый RPC в прод не берём: в нём нет навигации по дереву. Делаем свой sidecar на SDK.
- Между UI и ядром — тонкий адаптер, чтобы ядро можно было заменить (OpenClaw в итоге ушёл с ядра Pi).

## 3. Принципы ядра (ADR, подробно в `research/00-synthesis.md`)

1. **Кэш-ориентированный контекст.** Статичный промпт и набор тулов на сессию. Всё динамическое дописывается в хвост. Профиль, модель и effort фиксируются на сессию. Режимы переключаются текстом, без смены тулов.
2. **Профиль совместимости каждой модели и каждого поставщика.** Поля рассуждений, формат thinking, семплинг, `tool_choice`. Pi за нашим URL сам ничего не определит.
3. **Слой надёжности:**
   - таймауты bash и стрима;
   - починка аргументов;
   - детектор псевдовызовов и зацикливания;
   - лимит шагов и денежный лимит на задачу;
   - повторы по типу тула (повторять только безопасные);
   - реестр фоновых процессов и портов.
4. **Плоский `Edit`** в стиле Claude Code. Нечёткое совпадение — только с показом применённого фрагмента. Для больших файлов — правка по диапазону строк.
5. **Управление выводом тулов:** лимит, файл + превью, начало и конец при ошибке.
6. **Проверка — главный рычаг:**
   - быстрый синтаксис после правки;
   - тесты на внешнем стоп-гейте («до зелёного», с лимитом);
   - тесты только для чтения;
   - доказательства собирает харнес.
7. **Одна модель пишет, остальные читают и советуют.**
8. **Модель для роли выбирает харнес, поставщика выбирает шлюз.** Переключение модели — только на границах подзадач.
9. **Промпт по классу модели.** Топам — абстрактная цель и «копни глубже». Дешёвым — чёткий регламент.
10. **Профиль — слоистый конфиг (база → профиль → пользователь).** В v1 3–4 слота: промпт, тулы и скиллы, роли моделей, политика.
11. **Память** — см. раздел 6.
12. **Откат всего рабочего дерева на каждый шаг** (дизайн снапшотов OpenCode, с учётом `.gitignore` и лимитом размера). Это наше отличие от конкурентов.
13. **Безопасность:**
    - сначала детерминированные меры: песочница, правила команд, подтверждения;
    - инструкции из репозитория всегда недоверенные;
    - вычистка секретов до отправки.
14. **Протокол UI ↔ ядро по образцу Codex app-server:** Thread/Turn/Item, подтверждения как запросы ядра к клиенту.
15. **Evals:** парные сравнения, стоимость на решённую задачу, канарейки поставщиков.

## 4. Для казуалов: «слой намерений» и «диспетчер»

### 4.1 Слой намерений (расплывчатый запрос → хороший результат)
1. **Понять задачу:** тип и домен.
2. **Бриф.** Не больше 2–3 вопросов, только **кнопками с вариантами** и готовым вариантом по умолчанию. Есть кнопка «просто сделай»: тогда агент делает допущения и явно их помечает.
3. **Если пользователь не знает, чего хочет** (стиль, дизайн), агент показывает 2–3 направления с превью и даёт выбрать (паттерн moodboard).
4. **«Глубже, а не больше»** (по образцу скилла be-ambitious, MIT). Планировщик отвечает на четыре вопроса: что сделал бы профи, с каких исходников он бы начал, какие готовые методы и инструменты есть, чем проверить результат.
5. **«Поиск готового»** перед написанием своего — против изобретения велосипедов. По эксперименту E3 одно правило поднимает долю готовых решений с 67% до 94%. Плюс проверка, что пакет существует в реестре.
5a. **Схема по типу результата (E2):**
    - сайты и приложения: премиум-планировщик пишет ТЗ, дешёвый исполнитель делает — 82% побед;
    - тексты: короткий бриф или сразу делать — 70–71%.
5b. **Слой актуальных фактов:** в продуктовые задачи подставляем реальный каталог и цены (модели знают мир только на дату обучения).
6. **План простыми словами → выполнение → «что проверено»** человеческим языком.

### 4.2 Диспетчер (подтверждён экспериментом E1: агенты сами находят нужный скилл в 57–64%, диспетчер — в 90–100%)
- Каскад в интерфейсе `classifier` Pi:
  1. правила;
  2. локальный поиск по названиям и описаниям (ключевые слова + эмбеддинги);
  3. вызов диспетчера: Gemini 3.8 Flash или GPT-6 Luna (быстрый режим), Qwen 3.8 Flash (JSON);
  4. если ничего не подходит — молчим.
- Backend заменяемый: Jev, Luna, локальная decision-модель.
- Дешёвая быстрая модель на старте задачи и на границах подзадач. Выбирает скиллы, тулы и MCP, модели под роли, уровень риска и решает, нужно ли уточнение.
- Основной агент видит **только выбранное**: оно дописывается в историю, кэш не ломается.
- Статистика использования: неиспользуемые скиллы предлагаем отключить.
- Пользователь не видит ни скиллов, ни моделей. Максимум переключатель «быстрее / качественнее».

### 4.3 Совет экспертов (профиль «Повседнев»)
- Паттерн Roast Room (MIT): председатель, эксперты с весами, 3 раунда, поиск разногласий. Единогласие в первом раунде — тревожный сигнал. Обязательны «страж рисков» и «несогласный».
- Роли обезличенные (финансист, маркетолог…), без имён реальных людей.
- В UI визуализация «комнаты», где агенты спорят.

## 5. Роли моделей (предварительно; уточняется досье `research/10-model-roles.md` и экспериментами)

| Роль | Кандидаты | Основание |
|---|---|---|
| Исполнитель кода | DeepSeek V4.1 Flash 1017, Kimi K3, Qwen 3.8 | Все решили 100% простых задач. DeepSeek самый дешёвый ($0.02 за 1000 задач) |
| Планировщик / архитектор | Opus 5.5, Fable 5.1, GPT-6.1 | Сильнее на абстрактных целях. Подталкивать «копнуть глубже» и искать готовое |
| Ревьюер кода | Лёгкие модели **других семейств**, которые этот код не писали. На важных задачах — 2 мнения от разных семейств | Эксперимент: дешёвые ревьюеры нашли 16 из 16 багов. Опыт владельца |
| Диспетчер | Qwen 3.8 Flash, DeepSeek V4.1 Flash | 98% и 93% точности выбора скиллов |
| Зрение | Gemini 4 → Opus / GPT → DeepSeek; у GLM 5.3 зрения нет (только Flash) | Опыт владельца. Проверяется desk research |
| Тексты без нейрослопа | Сравниваем | Эксперимент в работе + голосование владельца |

## 6. Память (досье `research/09-memory-rag.md`)

- **v1:**
  - `MEMORY.md` и `USER.md` с лимитом, снимок фиксируется на сессию;
  - дневные заметки;
  - SQLite FTS5 (стемминг ru/en + trigram);
  - правки и удаления — через очередь подтверждения;
  - у каждой записи источник и доверие.
- **v1.x:** гибрид с `sqlite-vec` + локальная EmbeddingGemma 2 (175–314 МБ, скачивается по требованию). Затухание старых записей, MMR.
- **Код:** grep + карта репозитория (tree-sitter) + LSP. Векторный индекс кода не делаем (Cursor отказался от него в июле 2026).
- **Самообучение:**
  - факты добавляются сами;
  - скиллы-кандидаты копятся в «теневом режиме» и включаются только после одобрения пользователем или доказанной пользы в evals.

## 8. Telegram (профиль «Повседнев»)

- **Бот (Bot API):**
  - уведомления;
  - удалённое управление агентом;
  - закрытый доступ по умолчанию, привязка через одноразовый код.
- **Аккаунт (MTProto, GramJS):**
  - **правилами сервиса разрешён только отдельный аккаунт, который не жалко**, личный и рабочий — запрещено; при подключении показываем предупреждение и чекбокс;
  - сессия хранится только локально;
  - отправка — только с подтверждением;
  - лимиты частоты, массовые рассылки запрещены;
  - входящие сообщения — недоверенный контент.

## 9. Главные риски

1. **Маркетплейс как «тихий исказитель»:** подмена моделей, скрытые промпты, игнорирование параметров, отсутствие кэша. Закрываем канарейками и закреплением поставщика.
2. **Утечка кода и секретов через анонимных поставщиков.** Закрываем вычисткой секретов и политикой «что можно отправлять».
3. **Сложность собственной платформы** (sidecar, протокол, совместимость, снапшоты, память). Закрываем этапностью и берём готовое (Pi, Graphone, OpenCode, Hermes, Codex).
4. **Дрейф моделей и поставщиков.** Нужен постоянный мониторинг, а не разовые замеры.
5. **Windows:** песочница, bash, PTY.
6. **Подпись и дистрибуция из РФ.**

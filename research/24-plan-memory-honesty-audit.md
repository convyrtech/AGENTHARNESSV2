# 24 · План: продвинутая память, честность агентов, разбор сессий (v2)

Дата: 2026-10-25. Основа: `research/21-auto-memory.md`, `research/22-agent-honesty.md`,
`research/23-session-auditor.md`. Цифры и источники — там. Здесь решения, порядок и приёмка.
v1 прошёл независимую проверку свежим агентом: 15 замечаний, 2 блокирующих. Все учтены, список — §7.

## 0. Коротко

1. **Сначала мерить, но дыры чинить сразу.** Баги стоп-гейта и памяти (§1) идут первым слиянием. Остальное
   поведение меняется только после замера на бенче.
2. **Код — первая линия, ИИ-судья — вторая.** Сверка слов агента с его вызовами, страж старых тестов, проверки
   цитат памяти — кодом. Судья только с цитатой, которую проверяет код, и «нет проблемы» по умолчанию.
3. **Честный выход, но не лазейка.** Каждый возврат гейта разрешает сказать «не вышло», плюс инструмент
   `report_blocker`. Измерено: подгонка падает с 23,6 до 5,3% у 8 моделей, 0 из 280 у 7 моделей (research/22 §3).
   Блокер снимает возвраты, только если агент правда пытался и причину подтвердил код.
4. **Память сама, из слов пользователя, и чистится сама.** Экстрактор раз на сессию с сигналом, дешёвой
   моделью, вне хода. Его операции проверяет код. Удаления у модели нет. Забывает код, по виду записи.
   Экстрактор не видит файлов, сайтов, вывода инструментов, кнопок «что дальше» и вставок.
   **Цель: память и «авто» включены по умолчанию**, если A/B покажет пользу и нулевой вред. У владельца это
   включается раньше, для каждодневной работы.
5. **Разборщик сессий работает сам по расписанию, у нас.** Каждую ночь — по артефактам бенча и CI. Раз в
   неделю — по сессиям владельца. У пользователей — только детекторы-код и счётчики без текста, по согласию.
   Находки становятся задачами на код, задачами бенча, уроками и навыками. Новые тексты пишет человек через PR,
   пропускает бенч.
6. **Ничего не включается само.** Каждое изменение поведения — за флагом. Решение «по умолчанию» принимается
   по заранее заданному статистическому правилу (§5).

### 3.2 Что считается важным

Только слова пользователя с признаком долговечности (research/21 §7.1):
- явная просьба («запомни», «всегда», «никогда», «по умолчанию»);
- о себе и своём компьютере («я не программист», «у меня Windows 10»);
- как отвечать («пиши проще»);
- вкус результата («люблю тёмные сайты»);
- решения проекта, которых не видно в файлах («бот на Python»);
- повторное исправление (одно требование в двух разных сообщениях).

Не сохраняем: разовые просьбы, то, что видно в файлах, ошибки и пути, секреты, здоровье, деньги, предложения
агента, всё из вставок, кнопок, файлов и сайтов.

### 3.3 Когда и на какой модели

- В ходе: инструмент `memory` только для «запомни / забудь».
- Вне хода — экстрактор:
  - при закрытии или парковке сессии (главный процесс, а не каждый хост — у нас до 5 «припаркованных» хостов,
    их убивают через 10 мин простоя);
  - при старте — догон ≤2 необработанных сессий.
- Модель: самая дешёвая, которая на бенче держит JSON и даёт ≥80% верных. Кандидаты — deepseek-v4.1-flash,
  qwen3.8-max. Пока шлюз не отдаёт входные токены deepseek, цену считать по qwen.

### 3.4 Проверки кодом (каждая — unit)

1. `quote` — дословно из одного сообщения пользователя этой сессии (не из вставки, не из кнопки, не из навыка),
   ≥8 значащих символов.
2. Связь `text` ↔ `quote`: общая основа слова. Обязательный префикс «Пользователь… / В проекте…» и
   слова-маркеры («всегда», «запомни»…) в сравнении не участвуют. Порог подбирается на 100 размеченных парах
   (перефразы, отрицания): ложных отказов ≤10%.
3. **Полярность.** Слова «не / нет / без / больше не / никогда / перестал» сравниваются отдельно. Если
   полярность разная — это противоречие (supersede или карточка), никогда не reinforce и не отказ по tombstone.
4. Признак долговечности: маркер; повтор в другом сообщении; «я / у меня / мне / мой».
5. Секреты и угрозы — на текст и цитаты. При загрузке подозрительное в промпте заменяется на `[скрыто]`,
   в панели видно целиком.
6. Дубль — сходство основ ≥0,6 при той же полярности → reinforce.
7. Tombstone — хэши основ (не открытые основы), то же сходство при той же полярности → отказ.
8. ≤3 операции на сессию, ≤1 supersede; прогон, который вытесняет >25% записей, отклоняется целиком.
9. Закреплённое (`pinned`) меняется только через карточку.

### 3.5 Забывание (код, на старте сессии)

| Вид | Правило |
|---|---|
| `pinned` (пользователь закрепил или сказал «запомни») | Само не исчезает. Не упоминалось 180 активных дней — одна карточка «Это ещё актуально?» |
| `profile` (о себе и компьютере), `decision` (решения проекта) | По времени не исчезают. Только supersede или (для проекта) проект без активности 180 дней |
| `preference`, `correction` (auto) | В архив, если активных дней без упоминания > 30 × strength (потолок 180). Считаются дни, когда пользователь работал, а не календарь: перерыв в два месяца ничего не стирает |
| Переполнение | Вытесняются слабые `auto` по strength, затем по давности |
| История «было» | 90 дней с «Вернуть», потом удаляется. Истёкшее можно выучить снова |

### 3.6 Что видит пользователь (features)

- Карточка «Заметил и запомнил: …» · [Забыть] [Закрепить]; несколько — «Запомнил 3» · [Показать].
- «Обновил: было «…», стало «…»» · [Вернуть]. Вытеснение закреплённого — вопрос «Раньше вы просили «…».
  Теперь — «…»?».
- Панель «Память»: метка «вы просили / заметил сам», дата, цитата; «Было» (заменено, истекло, забыто) с
  [Вернуть]; переключатель «Замечать важное само». При первом включении — карточка с [Выключить].
- «Забыть всё» и выключение памяти стирают записи, кандидатов, историю и тексты журнала.

### 4.2 `report_blocker` — честный выход, а не лазейка

- Возвраты «почини» снимаются, только если:
  - после первого красного была хотя бы одна правка;
  - причину подтвердил код: `test_conflicts_request` называет проверку, которая есть в тесте, существовавшем
    до хода; `missing_file` называет путь, которого правда нет.
- Страж и статус работают и после блокера.
- Метрики бенча: «блокер до первой попытки» = 0; доля блокеров на решаемых задачах, включая трудные.

### 4.3 Законные изменения проверок

- Если в сообщении пользователя есть просьба изменить поведение («теперь скидка 15%», «округляй вниз»), страж
  не возвращает ход, а статус нейтральный: «Проверки обновлены по вашей просьбе».
- **Решение владельца:** можно ли агенту менять старый тест без такой просьбы, если он прямо говорит об этом?
  Рекомендация: нет — это блокер с вопросом пользователю. Без ответа владельца H-1 не включается по умолчанию.

### 4.4 Правило «готово при красном»

Слово «готово» модели не фильтруем. Итог хода показывает **карточка статуса от кода**. Модель её не пишет и
не может перекрыть. При красной проверке карточка говорит «Проверки не прошли» и стоит над текстом модели.

### 4.5 Что видит пользователь (ui / features)

- Строка статуса хода (ui): «Проверки прошли» · «Страница открылась без ошибок» · «Программу запускал — работает»
  · «Проверки не прошли» · «Нечем проверить» · «Агент поменял старые проверки — посмотрите» · «Проверки обновлены
  по вашей просьбе» · «Остались заглушки».
- Карточка `report_blocker` (features): «Не получилось: …», «Почему: …», «Что нужно от вас: …», кнопки.

## 5. Как решаем «включить по умолчанию»

- **Заранее заданное правило:** парное сравнение по задачам, данные всех моделей вместе. Требуется снижение
  целевого показателя ≥50% относительно, и бутстреп-интервал не включает 0. По каждой модели отдельно — только
  «не выше».
- **`ok` не хуже:** нет устойчивых переходов «зелёное → красное» на 16 обычных задачах (определение
  research/18 §11.4), n=5.
- **Разборщик (A-4):** снижение класса проверяется на задачах-провокациях H-0, не на обычных: там редкие события
  не видны.
- **Память (M-6):** задачи пользы и вреда (research/21 §7.10) + 16 обычных задач; меняется модель экстрактора
  и n=5. Польза «авто» засчитывается только на задачах, где «по просьбе» тоже могла справиться (пользователь
  сказал «запомни» в одном варианте и не сказал в другом).

## 7. Порядок

1. **Сразу:** «трубы» (harness) → слияние №1 (баги §1: harness — гейт; core — M-0); параллельно H-0
   (harness), M-sp (core), A-0 (ci).
2. Затем H-1 + H-1p, M-1 → M-2 → M-3, A-0s, A-1.
3. Затем M-3b + M-4 + карточки памяти (владелец пользуется каждый день), H-2 + строка статуса, M-5, A-2, A-3.
4. Затем H-3, H-4, M-6 (цифры владельцу, решение «по умолчанию для всех»), A-3p, A-4; A-5 — по решению владельца.

Каждое слияние — зелёный CI (включая layout и Windows), бенч там, где меняется поведение, запись в DIARY.

## 8. Что нужно от владельца

1. **Тесты:** можно ли агенту менять старый тест без просьбы, если он это прямо сказал? Рекомендую: нет, это
   вопрос пользователю (§4.3).
2. **Разметка:** просмотреть ~30 спорных случаев разборщика и памяти (по одному экрану на случай, «верно /
   неверно»).
3. **Хранилище:** где держать замороженный набор разметки и выборку сессий (несколько МБ; корпус ~2,5 ГБ можно
   пересобрать прогонами). Рекомендую: отдельный приватный репозиторий.
4. **Позже:** согласие на счётчики от пользователей (A-5) и итог M-6 «авто по умолчанию для всех».

## 9. Чего не делаем

- Не загружаем переписки пользователей и не гоняем судью у пользователя ради нашего обучения.
- Не даём модели удалять память. Не пишем тексты уроков и навыков без человека.
- Не пишем в промпт «аудитор смотрит» и не наказываем за рассуждения (учит прятать, research/22 §6.8).
- Не берём код из ELv2 / GPL / FSL / без лицензии — только идеи (списки в 21–23).

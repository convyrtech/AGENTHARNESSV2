# 24 · План: продвинутая память, честность агентов, разбор сессий

Дата: 2026-10-25. Основа: `research/21-auto-memory.md`, `research/22-agent-honesty.md`,
`research/23-session-auditor.md`. Цифры и источники — там; здесь решения, порядок и приёмка.

## 0. Коротко

1. **Сначала мерить, потом менять.** Наш бенч сейчас не провоцирует ни подгонку, ни вред памяти. Первые этапы
   каждой темы — задачи бенча и детекторы кодом. Поведение агента до замера не меняется.
2. **Код — первая линия, ИИ-судья — вторая.** Сверка слов агента с его вызовами, страж старых тестов, проверки
   цитат памяти — всё кодом. Судья только с цитатой, которую проверяет код, и «нет проблемы» по умолчанию.
3. **Честный выход дешевле любой защиты.** Текст возврата гейта с разрешением «не вышло — так и скажи» и
   инструмент `report_blocker`: измерено 23,6 → 5,3% подгонки у 8 моделей и 0 из 280 у 7 моделей (research/22 §3).
4. **Память сама, но из слов пользователя.** Экстрактор раз на сессию с сигналом, дешёвой моделью, в простое.
   Операции add / reinforce / update / supersede проверяет код (дословная цитата, связь с текстом, признак
   долговечности). Удаления у модели нет. Забывает код: 30 дней × подтверждения, потолок 180, закреплённое
   не трогается. Экстрактор не видит файлов, сайтов и вывода инструментов — главная защита от отравления.
5. **Разборщик сессий — у нас, не у пользователя.** Наши прогоны бенча, A/B, приёмки, догфудинг владельца. У
   пользователя — только детекторы-код и счётчики без текста, по согласию (152-ФЗ). Находки идут в рефлектор
   (S7) и превращаются в задачу на код, задачу бенча, урок из каталога или NO_ENTRY.
6. **Ничего не включается само.** Каждое изменение поведения — за флагом; по умолчанию — только после
   бенча: польза не хуже, вред 0, подгонка ниже.

## 2. Потоки и этапы

Четыре дорожки идут параллельно, файлы не пересекаются (кроме `flags.ts` — по одной строке на флаг).

### 2.1 Честность — дорожка **harness** (`app/packages/prsloy-harness`)

| Этап | Что | Приёмка |
|---|---|---|
| **H-0 мерить** | Задачи бенча: `conflicting-test`, `wrong-test`, `missing-file`, `blocked-download`, `write-tests` (8 мутантов), `legit-test-change` (контроль), `big-port-stub`; скрытые проверки в `fix-discount` и `agents-md-conflict`; исход `solved / honest_fail / disclosed_test_edit / cheat / false_done` из `check.mjs`; «агент-жулик» в `fake.json` | CI: жулик пойман. Живой замер qwen, deepseek, kimi (+ opus как эталон) × n=3 — в DIARY: подгонка, честный отказ, ложное «готово» по модели |
| **H-1 честный выход и страж** | Снимок проверки на начало хода (H1); страж старых тестов — вернуть тестовые файлы и обвязку к началу хода и прогнать (H2); сигнатуры хаков (H3, только сигнал ревьюеру и в статус; возврат при ≥2 сигналах); `report_blocker` (H4); текст T1 в каждом возврате (H5); замена строк в промпте (§6.3 research/22, бюджет 7 500) | Unit на каждый класс подмены и на «не флагать» (новый тест, переформатирование, переименование). Бенч: подгонка ниже H-0 у каждой модели; `ok` на 16 старых задачах не ниже; `legit-test-change` 3/3 без тревоги; `report_blocker` на решаемых ≤1 из 16 |
| **H-2 слова и факты** | Подсказка после 3-го красного прогона того же теста (H6); детектор заглушек (H7); сверка «проверил / тесты проходят» с журналом вызовов (H8); статус хода по фактам (H9, данные для карточки) | Бенч: `false_done` = 0, `unbacked_claim` = 0, длина финала не выросла |
| **H-3 полезность тестов** | Только если ход трогал тесты: статика (нет assert, `assert True`, только мок), fail-to-pass для «почини», ≤5 мутантов + «пустое тело», ≤60 с | `write-tests`: оценка мутантами с харнессом выше, чем без; p50 добавленного времени ≤20 с; Windows junction для `node_modules` |
| **H-4 ревьюер** | Список видов подгонки в промпте ревьюера, блок «сигналы харнесса (посчитано кодом)», куски тестов не обрезать первыми, финальный ответ модели ревьюеру не давать | `review-live`: каждый ревьюер даёт FAIL с цитатой на 2 диффах с подгонкой в ≥2 из 3 прогонов |

### 2.2 Память — дорожка **core** (`src/memory*.ts`, `main/prsloy/memory-ipc.ts`)

| Этап | Что | Приёмка |
|---|---|---|
| **M-0 баги** | Связь `text`↔`quote` (общая основа ≥5 букв) и в инструменте; tombstone по сходству основ ≥0,6; «Забыть всё» стирает журнал до хэшей; скан угроз при загрузке (подозрительное — `[скрыто]` в промпте, целиком в панели) | Unit: README-текст с чужой цитатой отклонён; пересказ забытого отклонён; после «Забыть всё» в журнале нет текста |
| **M-1 схема v2** | `origin user/auto`, `pinned`, `evidence ≤3`, `strength`, `lastSeen`, `validUntil`, `history`, `archive`; операции add / reinforce / update / supersede / archive / revert; журнал с `opId`; миграция v1 | v1 читается; revert байт-в-байт; supersede хранит историю; лимиты соблюдены |
| **M-2 сигналы и буфер** | `memory-signals.ts` (чистая функция: «запомни/всегда/никогда/по умолчанию», «я/у меня», повтор просьбы, откат хода); буфер только напечатанных пользователем сообщений; событие `memory.signal` без текста | 60 размеченных русских фраз: доля пойманных и ложных — в отчёт; в буфере нет вывода инструментов и вставленных блоков |
| **M-3 экстрактор в тени** | `memory-extract.ts`: простой 10 мин / закрытие / догон при старте (≤2), один JSON-вызов, ≤3 операции, всё через проверки кода; кандидаты в `candidates.jsonl`, в промпт ничего; флаг `autoMemory: "shadow"` | ≥50 сессий размечены: ≥80% кандидатов верны; 0 секретов; 0 цитат не из слов пользователя; цена на сессию с сигналом — в отчёт |
| **M-4 забывание кодом** | На `session_start`: auto в архив при `сегодня − lastSeen > 30 дн × strength` (потолок 180; для проекта — дни активности проекта); `validUntil`; вытеснение слабых auto при переполнении; архив 90 дней с «Вернуть»; `PRSLOY_NOW` для тестов | Тест на каждое правило; `pinned` не трогается; истёкшее можно выучить снова |
| **M-5 инструмент только явное** | `memory remember` требует маркер в цитате; «заражённый ход» (читал чужой файл или веб) — цитата только из последнего сообщения, иначе карточка «Запомнить?» | `poisoned-readme`, `delayed-trigger` зелёные; «запомни, что я на Windows» сохраняется |
| **M-6 A/B** | Бенч: 5 задач пользы, 8 вреда (research/21 §7.10) × 3 модели × n=3, «по просьбе» против «авто» | Решение: «авто» по умолчанию, только если польза ≥ «по просьбе» и вред = 0 |

Модель экстрактора: по умолчанию самая дешёвая, которая на бенче держит JSON и даёт ≥80% верных. Кандидаты:
deepseek-v4.1-flash, qwen3.8-max. У deepseek шлюз сейчас не отдаёт входные токены (DIARY, живой шлюз) — цену
считать по qwen, пока владелец не починит канал.

### 2.3 Что видит пользователь — дорожки **features** и **ui**

| Что | Кто | Когда |
|---|---|---|
| Карточка «Заметил и запомнил: …» · [Забыть] [Закрепить]; «Обновил: было … стало …» · [Вернуть]; вопрос при вытеснении закреплённого | features | M-4 → вместе с включением `autoMemory: true` |
| Панель «Память»: метка «вы просили / заметил сам», дата, цитата; «Недавно забыто» с истёкшим и вытесненным; переключатель «Замечать важное само»; первая карточка с [Выключить] | features | там же |
| Карточка `report_blocker`: «Не получилось: …», «Почему: …», «Что нужно от вас: …» с кнопками | features | H-1 |
| Строка статуса хода по фактам: «Проверки прошли» / «Проверки не прошли» / «Нечем проверить» / «Агент поменял старые проверки — посмотрите» / «Остались заглушки» | ui | H-2 |

Правило текста: если проверка красная, слова «готово» пользователь не видит никогда (research/22 §5).

### 2.4 Разборщик сессий — дорожка **ci** (свободна)

| Этап | Что | Приёмка |
|---|---|---|
| **A-0 код** | `scripts/audit-sessions.mts`, `src/audit/{ir,detectors}.ts`, `audit/rules.json`: нормализатор Pi JSONL + ledger/turns дизайна; 15 детекторов кодом (заявил без вызова, правка теста, заглушка, «запустите сами», петли, английский, запрещённое и др.); `findings.jsonl` с цитатами (вне git), `audit-events.jsonl` без текста | 0 токенов; положительная и отрицательная фикстура на детектор; на наших ≈220 сессиях находит ≥15 из 19 «кодовых» инцидентов DIARY; P ≥ 0,95 по ручному просмотру |

| **A-4 ворота** | `bench.mts --audit`, `abreport.py`; продвижение по S8: целевой класс ниже ≥30% относительно, `ok` не хуже, n ≥ 3; метрика — код или `check.mjs`, не судья | Первый кандидат: «"готово" только после зелёной проверки» снижает `claim:tests` |

Разборщик не виден агенту: правила и код вне папки проекта и промпта; PR, который чинит класс, не правит его
детектор (урок DGM, research/23 §7.6).

## 3. Порядок

1. Сразу и параллельно: **H-0**, **M-0**, **A-0** (всё — замер и баги, поведение не меняется), карточки ждут.
2. Затем **H-1** (самая дешёвая и доказанная мера), **M-1 → M-2 → M-3** (тень), **A-1**.
3. Затем **H-2**, **M-4**, **M-5**, **A-2**, **A-3**; UI-карточки по готовности.
4. Затем **H-3**, **H-4**, **M-6** (решение о «авто по умолчанию» — показать владельцу цифры), **A-4**.

Каждое слияние — зелёный CI (включая layout и Windows), бенч там, где этап меняет поведение, запись в DIARY.

## 4. Что показываем владельцу

- После H-0: таблица «подгонка / честный отказ / ложное готово» по моделям.
- После M-3: 10 примеров «что агент запомнил бы сам» из теневого режима и доля верных.
- После A-0 и раз в неделю: `REPORT-audit.md` — что нашли и что решили.
- Перед M-6: цифры пользы и вреда «авто» против «по просьбе» — решение за владельцем.

## 5. Чего не делаем

- Не загружаем переписки пользователей и не гоняем судью у пользователя ради нашего обучения.
- Не даём модели удалять память и не пишем новые тексты уроков из находок — только каталог.
- Не пишем в промпт «аудитор смотрит» и не наказываем за рассуждения (учит прятать, research/22 §6.8).
- Не берём код из ELv2 / GPL / FSL / без лицензии — только идеи (списки в 21–23).

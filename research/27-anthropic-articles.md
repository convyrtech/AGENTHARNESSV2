## Что новое и куда

1. **Промпт мерить на каждой модели.** Одна строка про многословность стоила 3 % на кодовых задачах, хотя неделями
   проходила тесты (E/april-23-postmortem). Наш A/B промпта — только qwen. → H-1p: прогон на qwen, kimi, deepseek.
2. **Память с происхождением и откатом:** у каждой записи — сессия-источник, откат, предпочтения агенту только на
   чтение, консолидация с проверкой (A/claude-managed-agents-memory; E/how-we-contain-claude: инъекция в памяти
   «перезагружается при каждом старте»). → авто-память #13–#16.
3. **Поиск:** фильтровать выдачу кодом до контекста (+11 % точности, −24 % токенов, A/improved-web-search-with-
   dynamic-filtering); неудачное чтение — «не прочитано», а не пусто (D/building-effective-agent-automations). →
   доработка #23 (пункт про пустой ответ DuckDuckGo).
4. **Число инструментов:** проблемы с «15–20+» (A/building-multi-agent-systems, 2026-01-23), а не 30–50. У нас ~10
   с поиском — держать ниже 15.
5. **«Удалять по умолчанию» откалибровано на сильных Claude.** Для слабых моделей проверяющие «остаются ценными»
   (A/building-multi-agent-systems). Наши проверки кодом — по делу; каждую всё равно доказывать замером.
6. **Примеры в описаниях инструментов** подняли точность параметров 72 → 90 % (E/advanced-tool-use, 2025-11-24), но
   для Claude 5 их убирают. Для qwen/kimi/deepseek — проверить на стенде.
7. **Разделение ролей** «планировщик / исполнитель / тестировщик» часто вредит; работает проверка «чёрным ящиком»
   (A/building-multi-agent-systems). → пересмотреть границы шагов «Дизайна».

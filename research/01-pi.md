**Главный тезис для нас.** Сегодня Pi — уже не «4 tools и всё». Это зрелый расширяемый движок. Почти каждая нужная нам функция имеет в нём точку расширения: virtual models для ролей моделей, `tool_result`/`agent_before_settle` для guardrails, `ContextEditEntry` для чистки контекста, skills, пакеты, MCP с отложенной загрузкой. При этом сам продукт намеренно не содержит permissions, сабагентов, plan mode, lint-петель и файловых чекпоинтов. Всё это придётся писать нам как extensions или как свой sidecar поверх SDK.

## 2. По измерениям

### A. Агентный цикл

**Что.** Два вложенных цикла. Внутренний крутится, пока есть tool calls или steering-сообщения. Внешний продолжается, если пришли follow-up сообщения.

**Как** (`packages/agent/src/agent-loop.ts`) [V]:
- `runLoop` (стр. 172–330). Steering опрашивается в трёх местах:
  - в начале (стр. 185);
  - после `prepareNextTurn`: там может идти компакция, и пользователь мог что-то напечатать (стр. 210–215);
  - после каждого `turn_end` (стр. 304).
- Follow-up проверяются, только когда агент «остановился бы» (стр. 311).
- Хуки конфигурации цикла:
  - `prepareNextTurn` подменяет context, model или thinking level между ходами;
  - `prepareRequest` делает то же для каждого запроса;
  - `finishTurn` возвращает решение `end`/`continue`;
  - `transformContext`, `convertToLlm`, `beforeToolCall`/`afterToolCall`, `getApiKey` (для истекающих токенов).
- **Условия остановки:**
  - `stopReason` `error`/`aborted` (стр. 254);
  - нет tool calls и пустые очереди;
  - все результаты батча имеют `terminate: true` (`shouldTerminateToolBatch`, стр. 700);
  - `finishTurn` вернул `end`.
- **Лимита шагов/ходов в ядре нет.** В `types.ts`/`settings-schema.ts` нет `maxTurns`/`maxSteps`. Бюджет придётся делать через extension: `turn_end` плюс `ctx.abort()` или блокировка tool call с `terminate`.
- **Обрезка по `length`.** Если ответ упёрся в `max_tokens`, *все* tool calls из него не исполняются и получают ошибку: «the response hit the output token limit, so its arguments may be truncated. Re-issue the tool call with complete arguments» (`failToolCallsFromTruncatedMessage`, стр. 488). Обоснование в комментарии: streaming-парсер «best-effort JSON salvage» может выдать аргументы, которые парсятся и валидны, но молча неполны.
- **Параллельные tool calls по умолчанию** (`executeToolCallsParallel`, стр. 596):
  - все calls проходят `prepareToolCall` (валидация и `beforeToolCall`) последовательно, затем исполняются через `Promise.all`;
  - результаты эмитятся в исходном порядке;
  - если хоть один tool объявлен `executionMode: "sequential"`, весь батч идёт последовательно;
  - мутации одного файла сериализуются через `withFileMutationQueue` по `realpath` (`coding-agent/src/core/tools/file-mutation-queue.ts`).
- **Steering и follow-up:**
  - steering доставляется после завершения tool calls текущего хода и до следующего LLM-вызова;
  - follow-up — после того, как агент отработал всё;
  - режим по умолчанию `one-at-a-time` (`agent.ts:255–256`);
  - Abort возвращает очередь в редактор; RPC `clear_queue` отдаёт очередь клиенту.
- **`agent_end` ≠ конец работы.** После него могут быть retry, recovery через компакцию или очередь. Финальный сигнал — `agent_settled` (docs/json.md).
- **Retry:** `retry.maxRetries=3`, экспоненциальный backoff от 2 с. Provider-level retries по умолчанию 0: «Provider retries can delay Pi from handling quota and usage-limit errors itself» (docs/settings.md).
- **Cancellation:** `AbortSignal` проходит через стрим и tools; bash убивает дерево процессов (`killProcessTree`).

**Почему.** В docs/extensions.md прямо сказано: «`agent_end` is not a final-idle signal». Разделение событий нужно, чтобы retry/компакция/очередь не выглядели для UI как завершение.

**Применимость к нам.**
- Цикл годится как есть.
- Нужно добавить extension «budget guard»: лимит ходов и стоимости на run плюс детектор зацикливания. У OpenClaw есть `repetition-guard.ts`, адаптированный из Hermes Agent.
- Поведение при `length` особенно важно для дешёвых моделей с маленьким `max_tokens`. Брать.

### B. Контекст-инжиниринг и кэширование

**B1. Системный промпт** (`coding-agent/src/core/system-prompt.ts`) [V].

Промпт собирается из упорядоченных секций, каждая обёрнута в XML-тег с её именем: `preamble` (без тега), `tools`, `rules`, `docs`, `addendum`, `project_context`, `skills`, `cwd` и пользовательские секции.

Преамбула дословно: «You are an expert coding assistant operating inside pi, a coding agent harness. You help users by reading files, executing commands, editing code, and writing new files.» (стр. 155–156).

Правила (`buildRules`, стр. 88–125):
- дедуплицированные guidelines от tools и от расширений;
- плюс «Be concise in your responses» и «Show file paths clearly when working with files»;
- если нет grep/find/ls, добавляется «Use bash for file operations like ls, rg, find».

Секция `docs` указывает модели на документацию Pi («read only when the user asks about pi itself…»). Это механизм самомодификации.

Даты и времени в промпте нет. Это хорошо для стабильного префикса.

Размер: моя оценка ≈1.2–1.4k токенов на промпт и схемы 4 tools без AGENTS.md и skills [U, ручной подсчёт символов]. Исходный тезис автора: «There does not appear to be a need for 10,000 tokens of system prompt… pi's system prompt and tool definitions together come in below 1000 tokens» (mariozechner.at, 2025-11-30; принцип до сих пор держится в коде).

**B2. Промпт как часть транскрипта** — главная новинка 2026 [V].
- Первый запрос пишет в сессию `system`-сообщение со *всеми* секциями и декларациями tools.
- Последующие изменения пишутся как system-сообщения-патчи: `sections` по имени (`null` удаляет секцию), `toolsAdded`/`toolsRemoved` (docs/session-format.md; `diffSystemPromptSections`, стр. 217; `declareToolChanges` в agent-loop.ts, стр. 342).
- Цель — append-only история и стабильный кэшируемый префикс.
- Провайдер получает изменения на месте, только если у модели `compat.supportsMidConvoSystemMessages` (и `supportsMidConvoToolAdditions` для tools). Иначе `collapseSystemMessages` сворачивает всё в ведущее system-сообщение (`ai/src/utils/transcript.ts:108–120`). Это переписывает префикс и даёт промах кэша.
- Для `openai-completions` **по умолчанию оба флага `false`** (`detectCompat`, `openai-completions.ts:1697`).
- RFC 0054 (Armin Ronacher, 2026-07-11) объясняет проблему: «changing it rewrites the stable prompt prefix and cannot accurately represent when an instruction became active». В RFC предлагался fallback через помеченное синтетическое user-сообщение, но в текущем коде его **нет**: только collapse [V].

**B3. Файлы правил** (docs/configuration.md) [V]:
- `AGENTS.md` / `AGENTS.MD` / `CLAUDE.md` / `CLAUDE.MD` из agent-dir, cwd и всех предков;
- `AGENTS.override.md` заменяет их только в своей директории;
- `SYSTEM.md` заменяет промпт, `APPEND_SYSTEM.md` дополняет (глобально и в `.pi/`);
- context-файлы грузятся **независимо от project trust**.

**B4. Skills — progressive disclosure** (`skills.ts:358`) [V]. В промпт идут только имя, описание и путь:

```
<available_skills><skill><name>…</name><description>…</description><location>…/SKILL.md</location></skill>…
```

Инструкция модели: «Use the read tool to load a skill's file when the task matches its description.» Есть принудительный вызов `/skill:name`. Реализована спецификация Agent Skills. Документация честно признаёт: «A model might fail to load a relevant skill».

**B5. Компакция** (docs/compaction.md; `core/compaction/*.ts`) [V].
- **Триггер:** `contextTokens > contextWindow − reserveTokens`, где `reserveTokens=16384`. Проверка идёт между ходами внутри run (в `prepareNextTurn`), перед новым промптом и как recovery после overflow-ошибки или раннего `length`: одна попытка compact-and-retry.
- **Что сохраняется:** последние `keepRecentTokens=20000`. Разрез делается по границам user/assistant/bashExecution/custom и **никогда по tool result**. Если один user-span длиннее бюджета, делаются два саммари: истории и префикса хода.
- **Повторные компакции** итеративны: промпт `UPDATE_SUMMARIZATION_PROMPT` с `<previous-summary>` и правилами «PRESERVE all existing information… move items from "In Progress" to "Done"».
- **Промпт саммари** (`compaction.ts:507`): «Create a structured context checkpoint summary that another LLM will use to continue the work». Строгий формат: Goal / Constraints & Preferences / Progress (Done / In Progress / Blocked) / Key Decisions / Next Steps / Critical Context, плюс «Preserve exact file paths, function names, and error messages».
- **Системный промпт саммаризатора** (`utils.ts:161`): «Do NOT continue the conversation… ONLY output the structured summary».
- **Сериализация разговора:**
  - текст вида `[User]: … [Assistant tool calls]: … [Tool result]: …`; обоснование: «This prevents the model from treating it as a conversation to continue»;
  - tool results обрезаются до 2000 символов (`utils.ts:94`);
  - **thinking не передаётся**: «replayed thinking is often not part of the model's live context»;
  - кумулятивно добавляются списки `<read-files>`/`<modified-files>`.
- **Модель и параметры:** саммари делает текущая модель сессии, или маршрут virtual model с `reason: "direct"`. В 1.4.0 сняли потолок вывода: «long reasoning no longer makes them fail». Запросы саммари не пишут в кэш (cache writes отключены). Есть пер-модельные `compaction.modelOverrides`.
- **Кастомизация:** `session_before_compact` может отменить компакцию или подставить свою (пример `custom-compaction.ts`, сторонний `pi-agentic-compaction`).
- **Branch summary** при `/tree`: тот же формат без Critical Context, суммирует покинутую ветку до общего предка.

**B6. `ContextEditEntry`** (0.87.0, 2026-09-21) [V]. Это append-only правка того, что увидит модель:
- `replacement: null` выбрасывает сообщение;
- иначе заменяется содержимое; сырая история, UI и биллинг не меняются;
- правки branch-relative.

Pi сам использует её, чтобы выбросить неудачную попытку перед retry после overflow. **Для нас это готовый механизм «tool-output pruning» без потери аудита.**

**B7. Управление выводом tools** [V]:

| Tool | Лимит | Что происходит при переполнении |
|---|---|---|
| `read` | head 2000 строк / 50 KB | «continue with offset until complete» |
| `bash` | tail 2000 строк / 50 KB | полный вывод в temp-файл, путь в результате; `[Showing lines X-Y of N. Full output: path]` |
| `grep` | 100 совпадений, 500 символов на строку | — |
| MCP | 20 KB | вырезается середина, полный текст в temp-файл |
| codemode | `max_output_tokens=10000` | — |

**B8. Кэш** [V]:
- `prompt_cache_key` = sessionId: только для api.openai.com или long retention.
- `cacheControlFormat:"anthropic"` ставит `cache_control` на системный промпт, последний tool и последнее сообщение прямо в chat-completions payload. Автодетект только для `openrouter` + `anthropic/*` (`openai-completions.ts:1088–1146, 1662`).
- Session-affinity заголовки.
- `cacheWarming` (`off|streaming|idle`): только если у модели объявлен `promptCache` lifetime и ожидаемая экономия ≥ $0.05.
- `showCacheMissNotices` показывает промахи кэша.
- Смена thinking level в середине сессии сохраняет кэш для GPT-6 (1.3.0).

**Применимость к нам.**
1. На нашем relay compat не определяется автоматически (детект по URL). **Каждой модели в `models.json` нужно явно прописать compat.** Иначе Pi пошлёт роль `developer` (дефолт `supportsDeveloperRole=true` для «стандартного» URL, стр. 1666) и `store:false`, которые DeepSeek/GLM/Kimi/Qwen через relay могут отвергнуть [V-код; U-поведение relay].
2. Для Claude за relay включить `cacheControlFormat:"anthropic"`, если relay пробрасывает `cache_control` (проверить экспериментом).
3. Пока нет mid-convo system: любая смена профиля, skills или MCP-секции ломает префикс. Значит, профиль надо фиксировать на старте сессии, а динамику делать через custom messages / deferred tools.

### C. Tools и формат правок

**Набор** [V]:
- по умолчанию `read`, `bash`, `edit`, `write` (`system-prompt.ts:64`);
- опционально `grep`, `find`, `ls`, `powershell` (только нативный Windows), `codemode`, `tool_search`.

Автор (2025-11-30, принцип в силе): «these four tools are all you need for an effective coding agent».

**`edit`** (`tools/edit.ts`) [V]. Схема:

```ts
{ path: string, edits: Array<{ oldText: string /* "Exact text… must be unique in the original file and must not overlap…" */, newText: string }> }
```

Описание tool: «Edit a single file using exact text replacement. Every edits[].oldText must match a unique, non-overlapping region of the original file. If two changes affect the same block or nearby lines, merge them into one edit…».

Guidelines в промпт:
- «When changing multiple separate locations in one file, use one edit call with multiple entries»;
- «Each edits[].oldText is matched against the original file, not after earlier edits are applied»;
- «Keep edits[].oldText as small as possible while still being unique».

Семантика:
- все правки матчатся против **исходного** файла;
- сначала точный поиск, затем fuzzy: NFKC, обрезка хвостовых пробелов, «умные» кавычки → ASCII, тире → `-`, спец-пробелы → пробел (`edit-diff.ts:34–56, 207`);
- BOM и CRLF сохраняются;
- в ответе `Successfully replaced N block(s)`, в `details` — diff и unified patch.

Ошибки сформулированы как подсказки:
- «Could not find the exact text in X. The old text must match exactly including all whitespace and newlines»;
- «Found N occurrences… Please provide more context to make it unique»;
- «No changes made… might indicate an issue with special characters».

**Ремонт кривых вызовов** (`prepareEditArguments`, стр. 103). Комментарий: «Some models (Opus 4.6, GLM-5.1) send edits as a JSON string instead of an array. Others send a single edit object». Поддерживается и legacy-форма `oldText`/`newText` на верхнем уровне.

Есть `constrainedSampling: {type:"json_schema", strict:"prefer"}`, но для openai-completions `supportsStrictMode=false` по умолчанию.

**`bash`** (`tools/bash.ts`) [V]:
- **непостоянный шелл**: каждый вызов — новый процесс (`spawn(shell, [...args, command])`, `detached` на *nix);
- таймаут опционален: «Timeout in seconds (optional, no default timeout)»;
- abort убивает дерево процессов;
- структурированный вывод `{output, truncated, full_output_path, exit_code, wall_time_seconds}`;
- в env передаются `PI_SESSION_ID`, `PI_MODEL` и др.;
- расширяется через `BashOperations` (SSH/VM), `commandPrefix`, `spawnHook`.

Фоновых процессов нет by design. Обоснование автора (2025-11-30): «Background process management adds complexity… process tracking, output buffering, cleanup on exit» — вместо этого tmux.

**Валидация аргументов** (`ai/src/utils/validation.ts:317`) [V]:
- коэрсия типов: TypeBox `Value.Convert`, нормализация `null` у опциональных полей;
- при провале модель получает «Validation failed for tool "X": - path: message … Received arguments: {…}»;
- неизвестный tool → «Tool X not found»;
- ошибки tool становятся `isError` результатами, а не исключениями цикла.

**Codemode** (docs/codemode.md) [V]. Модель пишет JS, он исполняется в QuickJS без Node, сети и таймеров, только через `tools.*`.
- Плюсы: параллельные вызовы, фильтрация больших результатов до попадания в контекст, `searchTools()` (BM25), `store()`/`load()` в транскрипте.
- Лимиты: 256 MB, 2 воркера на процесс.
- 1.0: «About 40% fewer prompt tokens, and errors that tell the model how to recover».

**Применимость к нам.**
- Для дешёвых моделей `str_replace`-подобный edit с fuzzy-нормализацией и подсказывающими ошибками — разумная база.
- Стоит сравнить его с hash-anchored правками oh-my-pi. Заявлено «Grok Code Fast 1: 6.7% → 68.3%» (README oh-my-pi, 2026-10; исходный пост blog.can.ac 2026-02-12) [U — vendor claim].
- Codemode с QuickJS хорош для «Daily»-профиля (MCP, данные). Для слабых моделей писать JS может оказаться хуже, чем прямые tool calls [U, проверить экспериментом].

### D. Поведение по моделям и провайдерам

**Абстракция** (`ai/src/api/openai-completions.ts`, 1754 строки) [V]. Compat-матрица `openai-completions` (docs/models-configuration.md):
- `thinkingFormat`: `openai`, `openrouter`, `deepseek`, `zai`, `qwen`, `qwen-chat-template`, `chat-template`, `together`, `baseten`, `string-thinking`, `ant-ling`;
- `requiresReasoningContentOnAssistantMessages` (автовключение для DeepSeek);
- `requiresThinkingAsText`, `requiresToolResultName`, `requiresAssistantAfterToolResult` — последний вставляет синтетическое «I have processed the tool results.»;
- `maxTokensField`, `supportsStrictMode`, `cacheControlFormat`, `supportsMidConvoSystemMessages`, `thinkingTokenBudgetField` (vLLM/Qwen/llama.cpp), `zaiToolStream`.

**Reasoning passback** [V]:
- thinking-блоки той же модели отправляются обратно в поле, откуда пришли (`reasoning_content` / `reasoning` / `reasoning_text`), или как `reasoning_details` (OpenRouter-стиль, зашифрованное) (стр. 1320–1407);
- **thinking другой модели выбрасывается** (`transform-messages.ts`, 1.3.0). Комментарий: «Signatures and encrypted reasoning are only valid for the model that produced them, and sending readable thinking as plain text makes the new model treat it as part of the visible reply».

**Межпровайдерный handoff** [V]:
- ID tool calls нормализуются (Responses-ID в 40 символов);
- осиротевшие tool calls получают синтетический `"No result provided"`;
- assistant-сообщения с `error`/`aborted` не реплеятся;
- картинки для не-vision моделей заменяются плейсхолдерами.

**Сэмплинг** [V]:
- `samplingParams` и `samplingParamsByThinkingLevel` (1.0.2), только для OpenAI-совместимых API;
- `thinkingLevelMap` переводит уровни Pi (`off…max`) в значения провайдера.

**Промпт по семействам: в ядре его нет.** `buildSystemPromptSections` не принимает модель [V]. Пер-модельная адаптация возможна только через `before_agent_start`. Сравнение: oh-my-pi заявляет «prompts: adjusted relentlessly for each model» [U].

**Virtual models** (docs/virtual-models.md, 0.99.0) [V]. Это главный механизм ролей:
- `pi.registerVirtualModel({provider, id, route(request, ctx)})` выбирает физическую модель и thinking на **каждый запрос**;
- `request.reason ∈ user|continuation|retry|direct`, плюс `previous`/`failed`;
- `state` хранится на ветке сессии и переживает компакцию;
- провайдер видит только физическую модель; assistant-сообщения называют реальную модель; `/session` показывает стоимость по моделям;
- если окно маршрута меньше контекста, Pi компактит перед запросом.

Рекомендация авторов: «Returning `previous` for `continuation` and `failed` for `retry` keeps prompt caches and thinking signatures valid. Switching models between turns is allowed but loses the prompt cache.»

Пример `jev-router.ts`: план на сильной модели → после первого успешного `edit`/`write` переключение на дешёвую, «accepting a single prompt-cache miss». Это ровно наш «planner/advisor → cheap executor».

**Применимость к нам.**
- Роли (cheap executor / premium planner / summarizer) естественно выражаются virtual model плюс отдельные nested-вызовы через `ctx.modelRegistry.streamSimple()`.
- Claude через chat-completions relay: thinking-подписи Anthropic в стандартном chat-completions не проходят, если relay не поддерживает `reasoning_details` как OpenRouter. Вероятно, для Claude/Fable за relay придётся либо выключать thinking в многоходовых tool-циклах, либо делать свой провайдер `streamSimple` под формат relay [U — требует проверки].

### E. Состояние и сессии

**Формат** (docs/session-format.md, v3) [V]:
- JSONL `~/.pi/agent/sessions/--<path>--/<ts>_<uuid>.jsonl`;
- первая строка — header (`cwd`, `parentSession`);
- далее записи с `id` (8 hex) и `parentId`, то есть дерево в одном файле;
- типы записей: `message`, `model_change`, `thinking_level_change`, `usage`, `compaction` (с полным `systemMessage`-чекпоинтом), `context_edit`, `branch_summary`, `custom` (вне контекста), `custom_message` (в контексте), `label`, `session_info`;
- текущая позиция — leaf; контекст строится обходом leaf→root с учётом последней компакции и правок (`buildContextEntries` → `buildSessionProjection` → `buildSessionContext`).

**Операции** [V]:
- `/tree` переходит к любой записи *в том же файле*, опционально с саммари покинутой ветки;
- `/fork` создаёт новый файл от user-сообщения, `/clone` копирует активную ветку;
- labels работают как закладки.

**Долговечность** (`session-manager.ts:1172–1188`) [V]:
- файл создаётся лениво, при первом user/assistant сообщении;
- дальше `appendFileSync` построчно, **без fsync**;
- при загрузке оборванная последняя строка игнорируется и чинится (стр. 655–668);
- стриминговые частичные сообщения не пишутся, assistant пишется на `message_end`;
- при падении во время tool-исполнения tool call остаётся без результата, а при реплее получает синтетический «No result provided» (`transform-messages.ts`).

`pi-durable` решает это по-настоящему, но он экспериментальный: «every step of a run is a task that stores a checkpoint before it moves on… unsafe tools are reported to the model instead of repeated» (earendil.com/posts/pi-durable, 2026-10-01). Пост также говорит: «It does not replace the Pi coding agent».

**Файловые чекпоинты.** В ядре их нет [V]. Пример `git-checkpoint.ts` (53 строки):
- на каждом `turn_start` делает `git stash create`;
- ref хранится в памяти (`Map`) и очищается на `agent_settled`;
- восстановление предлагается только при fork.

Следствия: не ловит untracked-файлы, не переживает рестарт и не привязан к записям дерева [V-код; следствия — мой вывод].

**Применимость к нам.** Формат дерева и `custom`-записи подходят для «session tree with file rollback». Файловые снапшоты надо делать самим (теневой git-репо или content-addressed store) с привязкой к `entryId` в `custom`-записях. Тогда `/tree` восстанавливает и код, и контекст. Это одно из главных мест расхождения.

### F. Расширяемость

**Extensions** (docs/extensions.md) [V]. TS-модули грузятся через `jiti` без сборки, factory получает `ExtensionAPI`.

События по группам:
- ввод: `input`, `before_agent_start` (структурированные `systemPromptOptions` — правка секций, а не полная замена);
- run и ход: `agent_start/end`, `turn_start/end`, `context`, `context_with_system`;
- провайдер: `before_provider_headers`, `before_provider_request`, `after_provider_response`, `provider_stream_event`;
- tools: `tool_call` (блокировать или мутировать вход), `tool_result` (переписать `content`/`isError`);
- завершение: `agent_before_settle`, `agent_settled`;
- сессия: `session_start/shutdown/before_compact/before_fork/before_switch/before_tree`, `project_trust`, `resources_discover`, `user_bash`, `cache_warming_decision`.

Ключевые хуки для guardrails:
- `turn_end` и `agent_before_settle` — «actionable boundaries»: могут добавить `custom_message`/`context_edit`/`compaction` и вернуть `continue: true` («Guard continuation conditions because an unconditional continuation can loop»);
- если обработчик `tool_call` падает, вызов блокируется (fail-closed).

Регистрации:
- `registerTool` с полями `exposure` (`direct|model-only|codemode|deferred|hidden`), `namespace`, `annotations` (MCP-хинты), `prepareLoadout`, `reachesTools`, `outputSchema`;
- `registerCommand`, `registerShortcut`, `registerFlag`, `registerProvider`, `registerVirtualModel`, `registerMcpServer`, `registerToolRenderer`, `registerMessageRenderer`;
- `sendMessage` / `sendUserMessage` / `appendEntry`, `setActiveTools` / `setModel` / `setThinkingLevel`;
- `ctx.executeTool()` — вложенные вызовы с теми же хуками permission;
- `pi.events` для связи между расширениями.

**Пакеты** (docs/packages.md) [V]:
- источники `npm:`, `git:`, локальный путь; манифест `"pi": {extensions, skills, prompts, themes}`;
- фильтры ресурсов в settings (`!pattern`, `+path`, `-path`);
- проектные пакеты только после project trust;
- хост-пакеты объявляются как `peerDependencies`.

**MCP** (0.99.0) [V]:
- stdio и streamable HTTP, OAuth;
- `exposure` по умолчанию `codemode`: tools не декларируются модели, а вызываются из скриптов;
- при `deferred` их подгружает `tool_search`;
- серверы перечислены в секции промпта `mcp_servers`, которая при изменении *дописывается в разговор*, «so earlier messages stay cached».

Смена позиции объяснена в «You said no MCP» (2026-09-29): «The biggest issue with MCP continues to be that it's hard to compose»; «the MCP of today is not the MCP of yesteryear»; «We believe the best way to positively influence something is to embrace it.»

**Hot reload.** `/reload` и `ctx.reload()` пересоздают runtime расширений. Код после `await ctx.reload()` относится к старому runtime [V].

**Как выразить «профиль».** Готовых профилей нет. Ближайшее — пример `preset.ts` [V]: JSON-пресеты `{provider, model, thinkingLevel, tools, instructions}`, `/preset`, `--preset`, состояние через `appendEntry("preset-state")`.

Полный профиль у нас = набор из:
1. `PI_CODING_AGENT_DIR` (свой agent-dir на профиль или общий плюс фильтры);
2. `settings.json` с `packages` и фильтрами ресурсов, `defaultTools`, `compaction`, `retry`;
3. `mcp.json`;
4. virtual model ролей;
5. секции промпта через `before_agent_start`;
6. UI-layout на нашей стороне.

**Применимость.** Расширяемость достаточна, чтобы не форкать ядро на старте. Риск — скорость изменений API (0.80→1.4 за 4 месяца, несколько Breaking Changes). pi-gui уже пришлось изолировать приватные API «compat seams» (docs/architecture.md pi-gui).

### G. Протокол UI↔core

**RPC** (docs/rpc.md, rpc-commands.md, `modes/rpc/rpc-types.ts`) [V]:
- JSONL по stdin/stdout, корреляция по `id`, stderr для диагностики.
- Команды:
  - ввод: `prompt` (с `streamingBehavior: steer|followUp`; ответ содержит `disposition: started|queued|handled`), `steer`, `follow_up`, `abort`, `clear_queue`;
  - сессии: `new_session`, `switch_session`, `fork`, `clone`, `get_fork_messages`, `get_entries` (курсор `since`), `get_tree`, `get_messages`, `set_session_name`, `export_html`, `get_session_stats`, `get_last_assistant_text`;
  - модель: `get_state`, `set_model`, `cycle_model`, `get_available_models`, `set_thinking_level`, `cycle_thinking_level`, `get_available_thinking_levels`;
  - очереди: `set_steering_mode`, `set_follow_up_mode`;
  - компакция и retry: `compact` (с `customInstructions`), `set_auto_compaction`, `set_auto_retry`, `abort_retry`;
  - прочее: `bash`, `abort_bash`, `get_commands`.
- События:
  - run: `agent_start/end/settled`, `turn_start/end`;
  - сообщения: `message_start/update/end` (дельты text/thinking/toolcall);
  - tools: `tool_execution_start/update/end`;
  - состояние: `queue_update`, `entry_appended`, `session_info_changed`, `thinking_level_changed`;
  - компакция, retry, `bash_execution_update`, `extension_error`.
- Extension UI сабпротокол:
  - блокирующие диалоги `select|confirm|input|editor` с `timeout`;
  - fire-and-forget `notify|setStatus|setWidget|setTitle|set_editor_text`;
  - `custom()` в RPC не работает.
- Фрейминг: делить строго по LF; Node `readline` нельзя, он режет по U+2028/2029. Нужно соблюдать backpressure.
- **Навигации по дереву на месте как RPC-команды нет.** `navigateTree` доступен только в контексте extension-команды (`rpc-mode.ts:329`). Значит, нужна своя slash-команда-расширение, вызываемая через `prompt`.

**SDK** (docs/sdk.md) [V]:
- `createAgentSession()`, `AgentSessionRuntime` (`newSession`/`switchSession`/`fork`), `SessionManager.inMemory()`, `session.subscribe()`;
- `prompt()` без указания steer/followUp во время стрима отклоняется;
- облегчённые `pi-ai/base` / `pi-agent-core/base` для бандлинга (0.79.8).

**Десктоп-обёртки** (что выбирали другие):
- **pi-desktop** (gustavonline; последний коммит 2026-04-13, *вне окна свежести, отстаёт от 1.x*):
  - Tauri, на каждую сессию отдельный процесс `pi --mode rpc` (`src-tauri/src/lib.rs:582`);
  - Rust — «тупая труба»: строки stdout пересылаются во фронтенд событием `rpc-event` вместе с `instance_id` и `generation`, чтобы отбрасывать события старых процессов (стр. 698–728). [V]
- **Graphone** (PriNova; 2026-06-23):
  - Tauri 2 плюс **собственный sidecar на SDK**, собранный bun (`services/agent-host`): один процесс мультиплексирует много `AgentSession`, общие `AuthStorage`/`ModelRegistry`;
  - свой JSONL-протокол `create_session`/`session_event{sessionId}`;
  - запинен на pi 0.79.8. [V]
- **pi-gui** (minghinmatthewlam; 2026-10-21):
  - Electron, SDK в main-процессе через `packages/pi-sdk-driver` («thin adapter… does not fork or reimplement runtime behavior»);
  - сессии — JSONL-файлы Pi как source of truth;
  - turn-capture через скрытые расширения на `agent_start`/`message_start`/`agent_settled`;
  - desktop-extension views в sandboxed iframe с транспортом Chord;
  - изолированные «compat seams» для приватных API. [V]

**Применимость.** Для Tauri + Rust-моста вариант Graphone («свой sidecar на SDK, мультиплекс сессий, наш протокол») выглядит сильнее, чем стоковый `--mode rpc`:
- даёт `navigateTree`, свои события профилей и ролей, один процесс на много вкладок;
- наши extensions всё равно грузятся;
- стоковый RPC можно оставить как fallback и тест-инструмент.

### H. Безопасность

**Позиция** [V]:
- README: «Pi does not include a built-in permission system… runs with the permissions of the user».
- docs/security.md: «Watching the transcript, using project trust, and reviewing changes do not create a security boundary»; prompt injection — «generally outside the security boundary».
- Автор (2025-11-30, принцип в силе): «security measures in other coding agents… mostly security theater».

**Project trust** [V]:
- контролирует загрузку `.pi/settings.json`, `.pi/mcp.json`, проектных extensions/skills/prompts и `SYSTEM.md`;
- не контролирует AGENTS.md и не контролирует tool calls;
- решения хранятся в `~/.pi/agent/trust.json`;
- в RPC без интерактива по умолчанию `ask` → ресурсы пропускаются; есть `--approve`/`--no-approve`.

**Примеры-расширения** [V]:
- `permission-gate.ts` — regex на `rm -rf`, `sudo`, `chmod 777`; без UI блокирует;
- `protected-paths.ts` — блок `write`/`edit` для `.env`, `.git/`, `node_modules/` (по substring — наивно);
- `confirm-destructive.ts` — подтверждение clear/switch/fork;
- `dirty-repo-guard.ts`;
- `sandbox/` — `@anthropic-ai/sandbox-runtime`: bubblewrap на Linux, sandbox-exec на macOS; конфиг `allowedDomains`, `denyRead`, `allowWrite`;
- `gondolin/` — built-in tools в QEMU micro-VM;
- в доках шаблон approval по MCP `annotations` (как в Codex).

Windows-песочницы в примерах нет [U — sandbox-runtime поддерживает только macOS/Linux, вывод].

OpenClaw добавляет «turn taint»: результаты tools из сети помечают ход, и это учитывается политикой записи памяти (`packages/agent-core/src/turn-taint.ts`, `session-transcript-accounting-policy.ts:105`) [V].

**Применимость.** Permission-модель (режимы ask/auto/yolo, allow-листы, approval по annotations, protected paths через `realpath`) и песочница — полностью наша зона. Хуки `tool_call`/`user_bash` и `BashOperations` позволяют встроить это без форка.

### I. Мультиагентность и сабагенты

- **Ядро:** сабагентов нет by design. README: «skips features like sub-agents and plan mode». Автор (2025-11-30, в силе): «You have zero visibility into what that sub-agent does… Using a sub-agent mid-session for context gathering is a sign you didn't plan ahead». [V]
- **Пример `subagent/`** [V]:
  - spawn `pi --mode json -p --no-session --model … --tools … --append-system-prompt <file>` (`index.ts:298–344`);
  - агенты — `.md` с frontmatter (`name, description, tools, model`);
  - режимы single / parallel (≤8 задач, 4 одновременно) / chain с `{previous}`;
  - каждому родителю возвращается ≤50 KB;
  - workflow-промпты scout→planner→worker и worker→reviewer→worker;
  - пример reviewer.md: «Bash is for read-only commands only… Assume tool permissions are not perfectly enforceable».
- **pi-durable:** сабагент = conversation, которым владеет задача tool. Abort каскадируется; `replay:"safe"` позволяет повторить после краха; фоновые задачи переживают abort родителя. [V, экспериментально]
- **oh-my-pi:** `task` с изоляцией в worktree, schema-validated yield, Agent Hub [V, README].

**Применимость.** Reviewer-сабагенты и эскалацию делаем сами:
- in-process через SDK (`createAgentSession` с in-memory `SessionManager`) или
- через process-spawn, как в примере.

In-process дешевле и даёт стриминг в UI. Нужно учитывать лимит `PI_CODEMODE_MAX_WORKERS`.

### J. Верификация и самоулучшение

**В ядре нет** lint/test-after-edit, ревьюеров, эскалации, best-of-N и LSP. Grep по `coding-agent/src` на lsp пуст [V].

**Хуки для реализации** [V]:
- `tool_result` после `edit`/`write`: запустить линтер или typecheck и дописать диагностику в результат (или `isError: true`);
- `agent_before_settle`: прогнать тесты; если красные — `custom_message` с выводом и `continue: true` (с ограничителем);
- `turn_end`: вызвать advisor-модель через `ctx.modelRegistry.streamSimple()` и вставить заметку.

**Референсы в форках:**
- **oh-my-pi «advisor»** (`docs/advisor-watchdog.md`) [V]:
  - отдельная модель-ревьюер (`modelRoles.advisor`) на своём контексте читает каждый ход и инжектит заметки aside/concern/blocker;
  - каденс `reviewMode: turn|agent-end`, `reviewInterval`, `maxNotesPerUpdate=4`;
  - fallback-цепочка моделей;
  - по умолчанию инструменты `read`/`grep`/`glob`;
  - в RPC/ACP выключен, пока хост явно не включит.
- **oh-my-pi:** «LSP wired into every write»; «Time-traveling stream rules» — regex-триггер обрывает стрим и инжектит правило как system reminder [V, README; эффективность — U].
- **OpenClaw:** `@openclaw/tool-call-repair` распознаёт tool calls, выданные моделью *текстом* (JSON/XML/`Action:`), и превращает их в настоящие; `repetition-guard` ловит зацикленный вывод (окна по 60 символов, ≥5 повторов) [V].

**Применимость.** Это ядро нашей «надёжности дешёвых моделей». Pi даёт точки входа, но не логику. Плана advisor из oh-my-pi и repair/repetition-guard из OpenClaw (MIT) — лучшие готовые образцы.

## 3. Топ-10 приёмов, которые стоит взять

1. **P0 — Virtual model как механизм ролей** (`registerVirtualModel`, `route()` по `reason`, sticky `previous`/`failed`, state на ветке). Executor на дешёвой модели, planner/advisor на премиум, переключение не чаще раза за фазу ради кэша. (docs/virtual-models.md, `jev-router.ts`)
2. **P0 — Явная compat-конфигурация каждой модели relay в `models.json`:** `supportsDeveloperRole:false`, `supportsStore:false`, `maxTokensField`, `thinkingFormat` (deepseek/zai/qwen…), `requiresReasoningContentOnAssistantMessages`, `cacheControlFormat:"anthropic"` для Claude, `samplingParamsByThinkingLevel`. Иначе автодетект по URL даст неверные дефолты. (`openai-completions.ts:1613–1750`)
3. **P0 — Append-only транскрипт с промптом и tools как system-патчами** плюс фиксация профиля на старте сессии. Мид-сессионные изменения отдавать через `custom_message` или deferred tools, чтобы не ломать префикс на relay без mid-convo system.
4. **P0 — Guardrail-хуки:** `tool_result` (lint/typecheck после правки, дописать в результат), `agent_before_settle` (тесты → `continue:true` с лимитом), budget/loop guard на `turn_end`.
5. **P0 — Edit-tool семантика Pi:** multi-edit против исходника, fuzzy-нормализация, сохранение BOM/CRLF, подсказывающие ошибки, ремонт аргументов (`edits` строкой или объектом). Параллельно поставить A/B с hash-anchored правками.
6. **P1 — Компакция Pi:** структурный чекпоинт-промпт, итеративное обновление, text-serialization с обрезкой tool results до 2000 символов, без thinking, кумулятивные file-lists, разрез не по tool result. Саммари отдавать дешёвой модели через `reason:"direct"` в роутере.
7. **P1 — `ContextEditEntry` для pruning:** выбрасывать старые большие tool outputs и неудачные попытки из контекста модели без потери аудита и биллинга.
8. **P1 — Защита от обрезанных по `length` вызовов:** не исполнять tool calls из такого ответа и отдавать модели инструкцию переиздать их. Плюс `transformMessages`: синтетические результаты для осиротевших calls, пропуск error/aborted.
9. **P1 — Свой SDK-sidecar (паттерн Graphone)** вместо стокового `--mode rpc`: мультиплекс сессий, свой протокол с `navigateTree`, профили и роли. Для диалогов сохранить семантику extension-UI (select/confirm с timeout), фрейминг строго по LF.
10. **P2 — Skills по Agent Skills spec** (name/description/location в промпте, чтение по требованию) и MCP с `exposure: deferred` + `tool_search` (или codemode для Daily-профиля). Сабагенты-ревьюеры по образцу `subagent/` и advisor из oh-my-pi.

## 4. Антипаттерны и ограничения (где придётся расходиться)

1. **Нет permissions и sandbox в ядре** (by design). Примеры наивны: substring-проверки путей, regex на bash. Песочница только macOS/Linux, а для Windows-десктопа это проблема [V; Windows — U].
2. **Нет файловых чекпоинтов, привязанных к дереву.** `git-checkpoint` использует `stash create` в памяти, без untracked, только при fork [V].
3. **Долговечность сессий слабая:** `appendFileSync` без fsync, частичный стрим теряется, нет replay-safe семантики tools. Это решает только экспериментальный `pi-durable` [V].
4. **Автодетект compat по URL.** На кастомном relay дефолты «как у OpenAI»: роль `developer`, `store`, `max_completion_tokens`, а mid-convo system выключен. Любое изменение промпта, tools или skills тогда ломает кэш [V].
5. **Нет лимита шагов, бюджета и детектора циклов** в цикле [V]. Нет ремонта текстовых tool calls (это есть у OpenClaw) [V].
6. **Один системный промпт на все семейства моделей** [V]. Пер-модельные промпты придётся делать нам через `before_agent_start`.
7. **RPC неполон для десктопа:** нет `navigate_tree`, нет кастомных событий расширений (кроме `entry_appended` и UI-строк), `custom()` UI не работает [V].
8. **Быстрая эволюция API.** От 0.80 до 1.4 прошло четыре месяца, были Breaking Changes, `@mariozechner/*` переименованы в `@earendil-works/*` [V]. pi-gui уже держит compat-слой под приватные API [V].
9. **Крупнейший интегратор ушёл в форк.** OpenClaw в релизе 2026.5.22 (2026-05, состояние подтверждено на 2026-10) «internalize the former Pi agent runtime… remove legacy package dependencies». Теперь «OpenClaw owns the built-in agent runtime… No external agent framework packages remain», от Pi остался только `pi-tui` (`docs/agent-runtime-architecture.md`, `package.json`) [V]. Это сигнал, что при глубокой интеграции (ретраи, failover, политика tools) поверх Pi-ядра в итоге форкают.
10. **Bash без фоновых процессов и без постоянного шелла** [V]. Dev-серверы и вотчеры нужно решать отдельно: tmux-подобный tool или наш PTY-менеджер.
11. **Windows:** bash идёт через Git Bash, нужен PowerShell-tool [V]. Конвертация путей WSL распознаёт только `/mnt/<drive>` [V]. Песочницы нет [U].

## 5. Открытые вопросы и что проверить экспериментом

1. **Relay + Claude:** проходит ли `cache_control` в chat-completions? Возвращаются ли `reasoning_details`/подписи? Можно ли вести многоходовой tool-цикл с thinking? Если нет — свой `streamSimple`-провайдер или thinking off.
2. **Mid-convo system** у DeepSeek/GLM/Kimi/Qwen через relay. Можно ли безопасно включить `supportsMidConvoSystemMessages`? Замерить cache-hit с флагом и без при смене skills/MCP.
3. **Edit-формат на дешёвых моделях:** Pi `edits[]` против hash-anchored (oh-my-pi) против apply_patch. Метрики: доля правок с первой попытки, токены, ретраи.
4. **Codemode против прямых tool calls** у слабых моделей. Метрики: ошибки JS, итоговое качество, экономия контекста.
5. **Порог компакции** для моделей со 128–256k окна. Какая модель саммаризует лучше всего на relay (цена/качество)? Что сохраняется из Critical Context после 3+ итераций?
6. **Advisor-каденс** (каждый ход против `agent-end`) и цена кэш-промахов при эскалации на premium. Где точка безубыточности?
7. **RPC против SDK-sidecar** на Windows: время старта Node/bun-бинаря, потребление памяти на N сессий, устойчивость при крахе одного `AgentSession`.
8. **Поведение project trust** в нашем UI, где нет TTY. Нужен свой обработчик события `project_trust` в user-level extension.

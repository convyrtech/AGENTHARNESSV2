# Харнесс плейбука «страница сайта»

| Файл | Что делает |
|---|---|
| `run.py` | дирижёр: шаг выбирает flow.py, на шаг — свежая сессия Pi (модели и бюджеты в `stages.json`) |
| `judge.py`, `second_opinion.py`, `check.py` | судья, второе мнение перед сообщением владельцу, проверки кода |
| `a6proxy.py` | прокси надёжности к a6: ключ держит он |
| `moves.py` | шаг 1: наборы приёмов движения в цветах и словах владельца |
| `baseline.py`, `simulate.py`, `abreport.py`, `owner-e8p.json` | чистый A/B: см. ниже |

Тесты: `python -m unittest discover -s playbooks/site/harness/tests` (без сети и моделей).

## A/B: дирижёр против одной сессии

Цель — сравнить два устройства харнесса на стабильном коде, с одним и тем же казуальным владельцем. Отличается только
устройство сессий:

- `run.py` — дирижёр;
- `baseline.py` — одна сессия Pi ведёт весь пайплайн, как `experiments/e8b/drive.py` в E8p. Сессия одна (`--session`
  держится весь прогон), модель Kimi K3.1 Pro. Общее с run.py берётся из него самого: рабочая папка, бюджет и детектор
  петель, проверка харнесса, второе мнение, судья в коде и сообщение после лимита его раундов. AGENTS.md тот же; в нём
  меняется только «один запуск — один шаг» (если текст поменяют, `baseline.py init` упадёт, а не разойдётся молча).

`simulate.py` — владелец по сценарию. После каждого вопроса он смотрит шаг (`flow.py --json`) и отвечает из
`owner-e8p.json`: ответы E8p по шагам. «5s» — шаг 5, пока не выбрана раскадровка, «7j» — сообщение после лимита
судьи, на шаге 8 он останавливается. Ответы на шаги, которых нет в сценарии, берутся из `*`, и отчёт их считает.

```bash
export PI_BIN=pi HARNESS_PROXY=http://127.0.0.1:8787    # как для run.py
H=playbooks/site/harness
python3 $H/simulate.py --driver run      --ws ~/ab/run/сайт  --record ~/ab/run.rec  --pipeline ~/design-pipeline \
        --materials ~/ab/материалы --key-file ~/.a6key
python3 $H/simulate.py --driver baseline --ws ~/ab/base/сайт --record ~/ab/base.rec --pipeline ~/design-pipeline \
        --materials ~/ab/материалы --key-file ~/.a6key
python3 $H/abreport.py compare ~/ab/run.rec ~/ab/base.rec --out ~/ab/report --python <python с Playwright>
```

- **Прогоны — по очереди, не вместе.** Деньги считаются по журналу a6 в окнах времени ходов: параллельные окна
  перекроются. Журнал отдаёт последние 1000 строк, поэтому `--key-file` забирает его сразу после прогона
  (`abreport.py cost`). Если журнал начинается позже прогона, отчёт пишет «неполный журнал».
- **Запись прогона** (`--record`) лежит вне папки агента. В ней:
  - `run.json`;
  - `turns.jsonl` (что отправлено, ключ сценария, окно времени, вопрос);
  - `events/` — события драйвера;
  - `state/` — HARNESS_STATE_DIR: журнал, сессии, судья;
  - `a6-rows.json`.
- **Материалы.** `--materials-with first` (по умолчанию) отправляет их с первым сообщением. `ask` отправляет их
  ответом на первый вопрос, как было в E8p.
- **Отчёт** — `report.md` и `report.json`:
  - деньги по журналу a6 (quota / 500000 = $) и по моделям;
  - минуты и вызовы агентов, сессии и запуски Pi;
  - вызовы судьи;
  - сообщения владельца, повторы вопросов, ответы не по сценарию;
  - до какого шага дошёл.

  Счётчик Pi в отчёте только для сравнения: кэш он считает по полной цене.
- **Слепой лист** `blind/sheet.png` — финальные страницы рядом, 390×844 и 1440×900 (`compare_sheet.py` пайплайна).
  Подписи А/Б ставятся в случайном порядке. Какая буква чья, записано только в `blind-key.json`: владельцу
  показывают один лист.

# STATUS — дорожка W4 «Дизайн» (`desktop/design`)

Этап 1 слит в main (`6162e93`). Этап 2 — ниже, ветка от main `6162e93`. Скриншоты: `screens/design-*.png` (ru, с брендом ui).

## Сделано

### 1. Сервис в main (`apps/desktop/src/main/design/`)

- `service.ts` ведёт движок, сам движок не переписан:
  - **Прокси.** `a6proxy.py` из venv на свободном порту (`--port 0`, порт читается из его первой строки).
    Upstream — адрес PRSLOY из настроек core (`prsloy.getState().baseUrl`). Ключ — из `prsloy.keyStore`.
  - **Ключ на диске.** Файл `userData/design/proxy/key-<uuid>`: 0600, на Windows `icacls /inheritance:r`.
    Он **удаляется сразу, как только прокси напечатал порт** (прокси читает ключ при старте).
    На диске ключ живёт меньше секунды. Для dev и тестов есть запасной вариант: env `PRSLOY_API_KEY` /
    `PRSLOY_BASE_URL`.
  - **Рабочая папка.** `<проект>/prsloy-design`, без проекта — `Documents/PRSLOY/prsloy-design`.
    `run.py init --page landing --pipeline <bundle>/design-pipeline`.
  - **Ход.** `run.py say` — дочерний процесс. Его JSONL разбирается (`events.ts`, все поля обрезаются) и
    идёт в renderer по `prsloy:design:event`. Каждое событие пишется в `harness/app-events.jsonl`: лента
    переживает закрытие вкладки. «Стоп» убивает дерево процессов: Windows `taskkill /T /F`, POSIX — группа.
  - **Выход из приложения.** Прокси и ход гасятся синхронно на `before-quit` и `process.exit`.
    `will-quit` не годится: `index.ts` выходит через `app.exit()`, и до фикса каждый прокси переживал
    приложение. Есть регрессионный тест.
  - **Pi.** `PI_BIN = [bundled node, extracted pi cli.js]` — тот же путь, что у TUI. Свой pi home
    `userData/design/pi-agent`:
    - `models.json`: провайдер `a6p`, как в `stages.json`, → локальный прокси, `apiKey: "local"`. Модели и
      compat берутся из каталога core (`buildPrsloyModelsJsonProvider`): без compat DeepSeek/Kimi отвечают
      400 на ходах с тулами;
    - `settings.json` с `shellPath` от core (Git Bash на Windows);
    - rg/fd скопированы из pi home core.
  - **Окружение.** Чистый env (`env.ts`, allow-list): `AWS_*`, `GH_TOKEN`, `*_API_KEY` и т. п. не
    проходят. Ставятся `PI_OFFLINE=1`, `PI_SKIP_VERSION_CHECK=1`, `PI_TELEMETRY=0`, `HARNESS_PROXY`,
    `DP_BROWSER_CHANNEL`, `DP_CHROMIUM_ONLY=1`. Шимы `python3` и `python3.cmd` ведут на venv: в venv на
    Windows нет `python3`, а AGENTS.md велит агенту `python3 -I …`.
  - **Картинки и видео.** Протокол `prsloy-design://ws/<id>/<путь>`. id — хэш папки (абсолютного пути в
    URL нет). Путь проверяется на попадание внутрь папки, symlink наружу запрещён. Range отдаётся для видео.
  - **Превью.** Статический сервер на 127.0.0.1 над `site/`: только GET/HEAD, без листинга, без выхода
    из корня. Открывает `site/landing/`.
- Подключение в `index.ts` — 4 строки: `APP_SCHEMES` (список схем переехал в `app-schemes.ts`) и
  `installDesign(...)`. Остальное — preload `window.zeno.design`, тип `DesignApi` в `@zeno/contracts`.

### 3. Вкладка «Дизайн» (`renderer/components/design/DesignPage.tsx`, `lib/design-state.ts`)

- Пункт «Дизайн» стоит сразу под «Новый чат».
- **Лента.**
  - Сообщения владельца — справа.
  - Карточка вопроса: текст, картинки и видео из `files`; `options` сгруппированы по вопросам
    (`[{q, options}]`, до 3 групп; старый плоский список читается как одна группа) — ряд кнопок на
    вопрос с подписью `q`, вариант с `recommended` помечен «рекомендую». Один вопрос отвечается кликом
    («А. …»), несколько — выбором в каждом ряду и «Ответить» («1А 2Б»). «Как рекомендуешь» шлёт ровно
    «как рекомендуешь». Файлы, приложенные до ответа кнопкой, уходят вместе с ним. Из текста убраны
    строки вариантов, строки вопросов и пути к картинкам: они уже стали кнопками и картинками.
  - Заметка «связь с моделью оборвалась, повторяю шаг…» и прочие `note` идут в тихий тикер, не ошибкой.
  - Поле ввода, приложить файлы (системный выбор, в `say` уходят только токены выбранных файлов),
    «Стоп» во время хода.
- **Прогресс.** Одна строка «Шаг N из 8: …»: 11 гейтов сведены в 8 шагов для владельца. Минуты идут
  после первой. Под строкой — тихий тикер последнего тула («edit design/landing/STATUS.md»).
- **stuck** → «Застрял на этом шаге.», «Подробнее» (сырой текст), «Попробовать ещё раз»
  (`run.py say --retry`).
- **Ход кончился без вопроса** (бюджет шагов) → «Сделал часть работы.» + «Продолжить». После «Стоп» —
  «Остановлено.» + «Продолжить». Падение процесса → «Что-то сломалось.» + «Подробнее».
- **done** → «Страница готова.», превью в `<iframe sandbox="allow-scripts">` с loopback, «Открыть папку»
  (`site/`).
- **Строки** лежат в `locales/design.{zh,en,ru}.ts` и подмешаны в середину каждой таблицы, чтобы не
  конфликтовать с дописыванием в конец.
- **CSP:** `prsloy-design:` для img и media, `frame-src http://127.0.0.1:*`.
- Бюджет строк `main.tsx` не поднят: `maybeMarkUnreadForRuntime` переехал в `store/unread-on-settle.ts`.

## Правки движка (отдельные коммиты, минимальные)

1. `3e189d0`:
   - `run.py`: env пропускает `DP_*` и `PI_OFFLINE`/`PI_SKIP_VERSION_CHECK`/`PI_TELEMETRY`;
     `HARNESS_PROXY` → `--proxy` для `judge.py` и `second_opinion.py` (порт прокси свободный, не 8787);
     `init` пропускает `git apply`, если копия уже пропатчена (метка sha256).
   - `a6proxy.py`: upstream с путём (`https://host/api/v1` → `/api/v1/…`), `http://` для локальных
     проверок, `--port 0` печатает настоящий порт.
2. `8a2b779`: `pipeline-fixes.patch` — канал браузера и режим только Chromium (см. выше), поверх правок
   дирижёра.
3. `5279e5f`: `run.py say --retry` сбрасывает лестницу моделей. Без этого «Попробовать ещё раз» после
   stuck по лестнице только повторяет stuck.

**Найденная ошибка движка, не чинил (решает дирижёр).** Если папка проекта — git-репозиторий,
`git apply --directory=design-pipeline` в `run.py init` молча пропускает все файлы патча (`Skipped patch`):
git ищет пути от корня внешнего репо. В приложении это обойдено пропатченной копией. Для запуска руками
нужен `GIT_CEILING_DIRECTORIES=<ws>` в этом вызове.

### Инструмент

`playbooks/site/harness/ask_owner.ts` — расширение Pi. run.py подключает его к каждой сессии шага через `-e`.

## Этап 12: быстрый черновик шага 5 — прототипы параллельно (research/20, «Вопрос 3»)

**За флагом `stages.json → 5.parallel`, по умолчанию выключен.** Для A/B без правки файла: `HARNESS_PARALLEL5=1`
включает, `0` выключает.

### Как работает

- Когда флаг включён и flow.py говорит, что прототипов (`05-proto/…`) нет, харнесс один раз за проект вместо сессии
  делает 2–3 одноразовых вызова «создай index.html целиком».
- Вызовы идут одновременно, на разных ступенях лестницы, от ступени шага вверх (лестница уже сужена `fit_ladder`
  по `HARNESS_MODELS`). Это Pi с `--no-tools --no-context-files --no-skills`: один ответ — один вызов.
- В задании каждого вызова:
  - блок дизайн-системы — `02-brand.md` и `materials/brand.json` с правилом «при конфликте побеждает дизайн-система»
    (идея screenshot-to-code, MIT; код не брали);
  - текст из FACTS.md и MESSAGE.md, выбранное движение, решения из STATUS;
  - свой характер: спокойный, смелый или с необычной механикой.
- **Таймаут на вызов** — `parallel_minutes`, 8 мин. Ошибка или пустой ответ одного вызова шаг не валит.
- **Результат.**
  - В работу идут первые два удачных: `05-proto/a` и `05-proto/b`. Выбор шага 5 по правилам flow.py — A, B или
    гибрид.
  - Лист снимает `compare_sheet.py`.
  - Дальше идёт обычная сессия шага с пометкой «прототипы собрал харнесс, не переделывай». Она смотрит лист,
    проверяет flow.py и спрашивает владельца через `ask_owner`.
  - Удачных меньше двух — шаг идёт старым путём, в журнале `proto_fallback`.
- **Бюджет шага не больше прежнего:** у следующей сессии шага 5 `max_calls` уменьшается на число вызовов прототипов.
- **Журнал:** на каждый вариант запись `proto` — модель, время, цена, токены, ошибка, номер пачки. `abreport.py
compare` показывает «Минут на шаг 5 (агенты + прототипы)», где пачка идёт столько, сколько её самый долгий вызов,
  и «Прототипов параллельно: удачных / всего, $».

### Тесты (`tests/test_parallel5.py`)

С заглушкой модели:

- три вызова идут одновременно: три по 1 с укладываются меньше чем в 2,6 с;
- в каждом задании есть дизайн-система, факты и свой характер;
- в работе только a и b, лист снят;
- один сломанный вызов не валит шаг; меньше двух удачных — старый путь;
- таймаут срабатывает;
- `run.py say` с флагом: три одноразовых вызова, потом сессия с пометкой спрашивает владельца инструментом;
- без флага — старый путь;
- метрики abreport.

С настоящим Pi: одноразовый вызов идёт без инструментов против поддельного сервера модели.

## A/B параллельного шага 5 (#21): готово к прогону

Прогоны с ключом делает дирижёр. Каждое плечо запускается одной командой. Плечи гоняются **по очереди, не
одновременно**: журнал a6 отдаёт последние 1000 строк, и окна ходов двух прогонов перекрылись бы.

### Команды

```
cd playbooks/site/harness
P=~/design-pipeline      # копия design-pipeline
K=~/.a6key               # ключ a6 (в вывод не попадает)
R=~/ab21                 # записи прогонов; --ws каждый раз новая пустая папка, --record вне неё
V=~/dpvenv/bin/python    # Python с Playwright и Chromium — для слепых листов

# плечо «выкл» (как сейчас), пара N
python3 simulate.py --driver run --parallel5 off --ws $R/off-N/ws --record $R/off-N/rec --pipeline $P --key-file $K
# плечо «вкл» (прототипы шага 5 параллельно), пара N
python3 simulate.py --driver run --parallel5 on --ws $R/on-N/ws --record $R/on-N/rec --pipeline $P --key-file $K
# отчёт пары N
python3 abreport.py compare $R/off-N/rec $R/on-N/rec --out $R/report-N --pipeline $P --python $V
```

- **Одинаково у обоих плеч:** сценарий владельца (`owner-e8p.json`) и лестница моделей (`stages.json`). Материалы,
  если нужны, — один и тот же `--materials <папка>` для обоих плеч.
- **`--parallel5`** ставит `HARNESS_PARALLEL5` для run.py и пишет плечо в `run.json`; отчёт подписывает столбцы
  «шаг 5 обычный» и «шаг 5 параллельно».
- **`--key-file`:** simulate.py сразу после прогона забирает журнал a6 (`abreport.py cost`).

### Сколько ждать

- **Шаг 5:**
  - выкл — до 40 мин (бюджет шага);
  - вкл — пачка из трёх прототипов идёт столько, сколько самый долгий вызов (не больше `parallel_minutes` = 8 мин),
    плюс сессия шага с урезанным бюджетом.
- **Прогон до шага 8:** по бюджетам `stages.json` — не больше ~4 ч (сумма `max_minutes` 247 мин плюс судья, до трёх
  раундов). Ожидаю 1,5–2,5 ч на прогон.
- **Предлагаю n = 3 пары:** 6 прогонов по очереди, ~10–15 ч стенки. Плюс отчёт и два слепых листа владельцу на пару.

### Что решает (качество «Дизайна», не только скорость)

Отчёт `report.md` даёт на каждое плечо:

- **судью** (judge.py, вердикт считает код):
  - вердикт и Blocker+Critical первого раунда;
  - раундов до PASS;
  - итог;
  - упёрлись ли в лимит раундов;
- **время:** минут на шаг 5, стенку, минуты агентов;
- **деньги** по журналу a6;
- **владельца:** вопросы и повторы вопросов.

Слепые листы для владельца, ключи лежат отдельно:

- `blind/sheet.png` — финальные страницы двух плеч (А/Б);
- `blind/step5.png` — все прототипы шага 5 обоих плеч вперемешку (А, Б, В…).

**Включаем `5.parallel` по умолчанию, только если качество не хуже.** Условия — по сумме n пар, и ни в одной паре
не должно быть явного провала:

1. **Судья, раунд 1:** Blocker+Critical у «вкл» не больше, чем у «выкл».
2. **Судья, раунды до PASS:** медиана у «вкл» не больше. Лимит раундов у «вкл» встречается не чаще.
3. **Взгляд владельца на финальные страницы:** в слепом листе он выбирает страницу «вкл» не реже, чем в половине
   пар (или говорит «равны»).
4. **Прототипы шага 5:** лучший по выбору владельца на `step5.png` — из «вкл» не реже, чем из «выкл».

И только потом скорость и деньги:

5. **Скорость:** медиана минут на шаг 5 у «вкл» ниже хотя бы на 30%, и стенка всего прогона не выше.
6. **Деньги** по журналу a6 у «вкл» не больше +20%.

Проваленное 1–4 оставляет флаг выключенным, как бы ни выиграло время.

### Что поправлено перед прогоном

- **Вердикт судьи в журнале — полями.** Раньше в журнал шёл хвост вывода judge.py в 400 знаков, и JSON со списком
  снимков в нём обрезался: качество из записи не читалось. Теперь run.py пишет в строку `judge` поля `round`,
  `verdict`, `findings`, `yes`, `no`. abreport.py читает и старые записи — по хвосту, где он целый.
- **Флаки теста шага 5 на Windows** (`test_parallel5`): вызовы заглушки теряли строку при одновременной дописке в
  один файл. Теперь у каждого вызова свой файл (bfc041f).
- **Тесты:** `tests/test_ab21.py`:
  - качество по журналу, включая старые записи;
  - вердикт не теряется при выводе длиннее 400 знаков;
  - список прототипов;
  - плечо в `run.json` и в отчёте.

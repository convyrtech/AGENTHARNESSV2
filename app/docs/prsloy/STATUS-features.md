Задание: топ из `research/19-analogs-code.md` §1. Код чужих проектов — только MIT/Apache-2.0/BSD, с атрибуцией в
`app/NOTICE.md`. Из `src/pro/` Dyad (FSL) ничего не взято. Проверки — без живой модели, на фейковом шлюзе.

Скриншоты: `docs/prsloy/screens/features-*.png` (снимает сам e2e).

## 1. «Выбрать на странице» (§1.5)

**Что видит человек.** В превью «Кода» под шапкой — кнопка «Выбрать на странице». Нажал — элементы страницы
подсвечиваются под мышью. Кликнул — в поле ввода появился блок с точным местом, последняя строка
«Что поменять здесь:», курсор после неё. Человек дописывает «сделай зелёной» и отправляет. Esc — отмена.

**Как устроено.**

- `main/preview-bridge/inspector.js` — скрипт-инспектор, урезанный порт bolt.diy `public/inspector-script.js`
  (MIT): подсветка, клик → `{tag, selector, path, text, html, page}`. `selector` — точный CSS-путь (ближайший
  уникальный `id`, дальше `:nth-of-type`), `html` — первые 300 символов `outerHTML`.
- `main/design/preview-server.ts`: опция `inject`. Только сервер превью «Кода» (`code-preview.ts`) вставляет
  `<script src="/__prsloy/bridge.js">` сразу после `<head>` в ответы `text/html` и сам отдаёт этот скрипт. Превью
  «Дизайна» и серверы, которые поднял агент, не трогаются: там нет скрипта, и кнопки нет.
- `renderer/components/PreviewFrame.tsx` (общий): необязательный `bridge`. Сообщение принимается, только если
  `event.source` — окно нашей рамки и `event.origin` — адрес превью; команды уходят только на этот адрес.
  `renderer/lib/preview-bridge.ts` проверяет форму сообщения и обрезает строки.
- `CodePreviewPanel.tsx`: кнопка появляется, только когда страница ответила `ready`. Блок для поля ввода —
  `pickedPrompt()`; в `main.tsx` он дописывается к черновику.

**Проверка.**

- unit: `main/preview-bridge/inspector.test.ts` (jsdom: подсветка, клик, точный селектор находит тот же элемент,
  Esc, чужие сообщения игнорируются), `design/preview-server.test.ts` (вставка только в HTML, тег в начале
  `<head>`, без опции скрипта нет), `lib/preview-bridge.test.ts`, `CodePreviewPanel.test.tsx` (кнопка только после
  `ready` с нашего адреса и из нашей рамки; выбор → текст в поле; Esc).
- e2e: `e2e/features-pick.spec.ts` — агент пишет страницу, превью, «Выбрать на странице», клик по кнопке
  «Записаться» → в поле точное место, селектор из блока находит ту же кнопку, текст доходит до модели.
  Скриншоты: `features-pick-1-before.png`, `features-pick-2-hover.png`, `features-pick-3-after.png`.

**Не сделано.** Поиск `файл:строка` по проекту (п. 3 в §1.5, «по желанию»): агент и так находит место по
селектору и коду. Серверы агента (`127.0.0.1:<порт>`) без прокси инспектор не получают.

## 2. «На странице ошибка → Починить» (§1.2)

**Что видит человек.** Открыл превью, а на странице что-то сломано. Над страницей плашка «На странице ошибка»
(или «Ошибок на странице: N») с первой ошибкой и кнопками «Починить» и «Скрыть». «Починить» отправляет агенту
одно сообщение: «Исправь ошибки на странице index.html. Что показывает браузер:» и список ошибок с местом
(`/js/app.js:12:5`, «не загрузился файл /img/logo.png»). Само ничего не отправляется — только по кнопке, иначе петля.

**Как устроено.**

- `main/preview-bridge/page-errors.js` (свой код, ~110 строк): `error` в фазе захвата (ошибки скриптов и файлы,
  что не загрузились), `unhandledrejection`, первые 5 `console.error`. Чужое «Script error.» без файла
  отбрасывается. Не больше 20 сообщений со страницы, повторы склеиваются. Стоит первым в `<head>`, поэтому слышит
  ошибки первых скриптов страницы.
- Тот же путь, что в п. 1: только наш сервер превью «Кода», только наша рамка и её адрес.
- `lib/preview-bridge.ts`: `addPageError` (до 10 разных), `pageErrorLine`, `pageErrorsPrompt`.
- `CodePreviewPanel.tsx`: плашка; «Починить» → `onSend` → `sendPrompt` в `main.tsx`, тем же путём, что
  «Повторить». «Обновить» и новая страница начинают с чистого листа.

**Проверка.**

- unit: `main/preview-bridge/page-errors.test.ts` (место ошибки, один раз; «Script error.» пропускается; файл не
  загрузился; promise; не больше 5 `console.error`), `lib/preview-bridge.test.ts` (разбор, лимит, текст),
  `CodePreviewPanel.test.tsx` (чужой адрес не показывает плашку; «Починить» шлёт текст только по клику;
  «Скрыть»; «Обновить»).
- e2e: `e2e/features-errors.spec.ts` — страница с падающим скриптом и без картинки → «Ошибок на странице: 2»,
  без клика к модели ничего не уходит, «Починить» → модель получает обе ошибки с местом.
  Скриншоты: `features-errors-1-before.png`, `features-errors-2-after.png`.

## 3. «Скачать архив» проекта в «Коде» (§1.4)

**Что видит человек.** В превью «Кода» кнопка «Скачать архив», и такой же пункт в меню проекта («…» у проекта
в боковой панели). Окно «Сохранить как» с папкой «Загрузки» и именем `<папка проекта>.zip`. После сохранения
папка с архивом открывается сама, в превью — «Архив сохранён: имя.zip». Отмена — тихо. Проект больше 200 МБ —
«Проект больше 200 МБ — архив не собрать.» (в меню проекта — окно ошибки).

**Как устроено.**

- `main/features/project-zip.ts`: обход проекта через `lstat` — ссылки не идём, наружу ничего не попадает.
  Пропуск: все точечные файлы и папки (`.env`, `.git`, `.venv`), `node_modules`, `venv`, `__pycache__`, `dist`.
  Предел 20 000 файлов и 200 МБ. Архив — существующий `main/design/zip.ts` (`zipFiles`), всё внутри одной папки.
- `main/features/ipc.ts`: свой IPC `prsloy:features:export-project-zip`, первым делом `assertTrustedSender`,
  папку проверяет `previewWorkspace` (не домашняя папка и не корень диска). Подключение в `main/index.ts` —
  2 строки. Контракт — `packages/contracts/src/features.ts`.
- renderer: `lib/project-zip.ts` (текст для человека), кнопка в `CodePreviewPanel.tsx`, пункт в `ProjectList.tsx`.

**Проверка.**

- unit: `main/features/project-zip.test.ts` (что входит и что нет, ссылки наружу не идут, предел, имя файла),
  `lib/project-zip.test.ts`.
- e2e: `e2e/features-zip.spec.ts` — окно сохранения подменено в main; архив читается `readZip`, внутри
  `index.html`, нет `.env` и `node_modules`, секрета из `.env` нет в байтах; отмена — без надписи.
  Скриншоты: `features-zip-1-before.png`, `features-zip-2-after.png`.

## 4. «История версий» (§1.8)

**Что видит человек.** В меню «…» чата — «История версий». Окно со списком: каждая просьба к агенту в этом
проекте («сделай меню», «сегодня 10:05»), новые сверху, до 50. У каждой строки «Вернуть» → вопрос «Вернуть эту
версию? Файлы станут как до «сделай меню». Нынешнее состояние останется в истории — его тоже можно вернуть.»
После возврата — «Ход откачен: вернул 3 файла», а наверху списка появляется «Перед откатом»: им можно вернуться
обратно. Пока агент работает, кнопки ждут: «Сначала остановите агента».

**Как устроено.** Только renderer, ядро не тронуто: `listTurns` и `undoTurn` уже есть (`STATUS-core.md`, п. 6).

- `lib/version-history.ts`: порядок, предел 50, подпись («Перед откатом», «(без текста)»), время («сегодня»,
  «вчера», дата).
- `components/VersionHistoryDialog.tsx` по образцу Dyad `VersionPane.tsx` (только идея, код свой).
  Возврат — `undoTurn(id)`; для строки-хода результат пишется в `undo-log`, поэтому «Откатить» под этим ходом в
  ленте тоже показывает «Ход откачен».
- `ThreadHeader.tsx`: пункт меню и окно, ~20 строк.

**Проверка.**

  возвратом, текст результата, запись в журнал отката, кнопки ждут во время хода, пустой список, отказ ядра).
- e2e: `e2e/features-history.spec.ts` — первая просьба пишет `index.html`, человек правит файл руками, вторая
  просьба; в истории 2 версии; «Вернуть» к первой → файла нет; «Перед откатом» → файл снова с ручной правкой.
  Скриншоты: `features-history-1-before.png`, `features-history-2-after.png`.

**Не сделано.** «Посмотреть старую версию» в превью (нужен `git archive` из теневого репозитория — правка ядра,

## 5. «Что дальше» (§1.7)

**Что видит человек.** Под последним готовым ходом — «Что дальше:» и 2–3 кнопки: после страницы «Сделай,
чтобы на телефоне тоже было красиво», «Добавь форму заявки», «Сделай дизайн ярче»; после бота — «Добавь боту
команду /help» и т. п. Клик ставит текст в поле ввода, курсор в конец, ничего не отправляет. Пока человек
печатает, во время хода, после ошибки и после хода без файлов кнопок нет.

**Как устроено.** Без лишнего вызова модели.

- `lib/next-steps.ts`: если модель закончила ответ тегом `<prsloy-next>` (строка на шаг), берём шаги оттуда.
  Правила взяты из Dyad `suggestedPrompts.ts` (Apache-2.0, атрибуция и копия лицензии: `app/NOTICE.md`,
  `app/licenses/dyad-Apache-2.0.txt`): учитывается только последний закрытый тег в самом конце, без пометок
  списка и повторов, до 3 шагов по 120 символов. Тег вырезается из текста ответа, даже недописанный во время
  потока. Без тега шаги подбираются по файлам, которые записал ход: страница, бот Telegram или другой код.
- `components/NextStepChips.tsx` в стиле примеров пустого чата. Встроено в `SessionTimelineContent.tsx`
  после последнего хода, `main.tsx` не тронут.
- Строку про тег в системный промпт «Кода» должна добавить дорожка harness (`packages/prsloy-harness` не
  трогаю). До этого работают запасные подсказки.

**Проверка.**

- unit: `lib/next-steps.test.ts` (последний тег, текст после тега, пометки, повторы, длина; вырезание из ответа
  во время потока; запасные шаги для страницы, бота и кода; только после последнего хода; не во время хода; не
  после ошибки), `components/NextStepChips.test.tsx`.
- e2e: `e2e/features-next.spec.ts` — после записи страницы 3 кнопки; клик ставит текст в поле, фокус там,
  к модели ничего не ушло; после ответа без файлов кнопок нет.
  Скриншоты: `features-next-1-before.png`, `features-next-2-after.png`.

## 6. «Снять часть страницы» во вложение (§1.9)

**Что видит человек.** В превью «Кода» кнопка «Снять часть страницы». Страница слегка темнеет, сверху
подсказка «Обведите рамкой нужное место. Esc — отмена.» Человек тянет рамку мышью — снимок этой части
появляется во вложениях поля ввода, в превью «Снимок добавлен к сообщению.» Он пишет «вот тут криво» и
отправляет: модель получает картинку (у всех моделей PRSLOY есть `input: image`).

**Как устроено.**

- Снимок берёт main: `webContents.capturePage(rect)` нашего же окна. Запроса «поделиться экраном» нет, в
  отличие от bolt.diy `getDisplayMedia` (взята только идея). Аннотатор Dyad под FSL — не смотрел и не брал.
- `main/features/capture-rect.ts`: проверка прямоугольника (числа, не меньше 8 px, внутри окна) и масштаб окна
  (`getZoomFactor`), чтобы при 125 и 150 % снималось то же место. Плотность экрана `capturePage` учитывает сам.
- `main/features/ipc.ts`: `prsloy:features:capture-preview` с `assertTrustedSender`. PNG кладётся туда же,
  куда вставленные картинки (`<temp>/zeno-attachments`), поэтому миниатюра во вложениях работает как обычно.
- renderer: `components/PreviewCaptureOverlay.tsx` (слой с рамкой, Esc), `lib/preview-capture.ts`. Перед
  снимком слой убирается и выжидаются два кадра, чтобы рамки не было на картинке. `main.tsx` — одна строка
  `onAttach`.

**Проверка.**

- unit: `main/features/capture-rect.test.ts` (округление, масштаб 1,25, обрезка по окну, мусор и «клик» —
  отказ), `lib/preview-capture.test.ts`, `CodePreviewPanel.test.tsx` (клик — не снимок; рамка → IPC с точным
  прямоугольником → вложение; Esc).
- e2e: `e2e/features-capture.spec.ts` — рамка мышью вокруг красного блока → карточка вложения с миниатюрой →
  отправка: в запросе к модели картинка (фейковая модель картинки не принимает, pi пишет «image omitted»), PNG на
  диске, размер не меньше нарисованного. Скриншоты: `features-capture-1-before.png`,
  `features-capture-2-frame.png`, `features-capture-3-after.png`.

## 7. Поиск по старым чатам (§1.6)

**Что видит человек.** Лупа в боковой панели (рядом с PRSLOY) открывает палитру. Пишет «доставк» или
«елок доставк» — под командами группа «Чаты»: название чата (или его первая просьба) и кусок текста, где нашлось.
Клик открывает чат так же, как клик в боковой панели.

**Как устроено.**

- `main/features/session-search.ts` — порт PiCove (PiDeck) `session-search.ts` (MIT, атрибуция в
  `app/NOTICE.md`, шапка в файле). Ищет прямо по JSONL-сессиям Pi в `<agentDir>/sessions/` (чаты без проекта) и
  в папках проектов. Совпасть должны все слова; «ё» = «е»; кэш по `mtime` и размеру; отрывок 40/120 символов;
  до 3 мест на чат, до 30 чатов, новые сверху. Вывод инструментов и имена приложенных файлов
  (`<attached-paths>`) не ищутся.
- IPC `prsloy:features:search-chats` с `assertTrustedSender`; папка агента — `PI_CODING_AGENT_DIR`, как в
  `harness-flags.ts`. Запрос обрезается до 200 символов.
- `lib/chat-search.ts` (от 2 букв, пауза 200 мс), группа в `CommandPalette.tsx`; `main.tsx` — одна строка
  `onOpenChat` → `switchThread`.

**Проверка.**

- unit: `main/features/session-search.test.ts` (все слова, ё/е, порядок, название, совпадений, вложения и вывод
  инструментов не ищутся, битые файлы, чаты прямо в `sessions/`), `lib/chat-search.test.ts`.
- e2e: `e2e/features-search.spec.ts` — два чата; «елок доставк» находит только первый (в нём «ёлок»); клик
  открывает его; «пицца» — чатов нет. Скриншоты: `features-search-1-before.png`, `features-search-2-after.png`.

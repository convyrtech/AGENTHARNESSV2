## 1. «Выбрать на странице» (§1.5)

**Что видит человек.** В превью «Кода» под шапкой — кнопка «Выбрать на странице». Нажал — элементы страницы
подсвечиваются под мышью. Кликнул — в поле ввода появился блок с точным местом, последняя строка
«Что поменять здесь:», курсор после неё. Человек дописывает «сделай зелёной» и отправляет. Esc — отмена.

**Как устроено.**

- `main/preview-bridge/inspector.js` — скрипт-инспектор, урезанный порт bolt.diy `public/inspector-script.js`
  (MIT): подсветка, клик → `{tag, selector, path, text, html, page}`. `selector` — точный CSS-путь (ближайший
  уникальный `id`, дальше `:nth-of-type`), `html` — первые 300 символов `outerHTML`.
- `main/design/preview-server.ts`: опция `inject`. Только сервер превью «Кода» (`code-preview.ts`) вставляет
  `<script src="/__prsloy/bridge.js">` сразу после `<head>` в ответы `text/html` и сам отдаёт этот скрипт. Превью
  «Дизайна» и серверы, которые поднял агент, не трогаются: там нет скрипта, и кнопки нет.
- `renderer/components/PreviewFrame.tsx` (общий): необязательный `bridge`. Сообщение принимается, только если
  `event.source` — окно нашей рамки и `event.origin` — адрес превью; команды уходят только на этот адрес.
  `renderer/lib/preview-bridge.ts` проверяет форму сообщения и обрезает строки.
- `CodePreviewPanel.tsx`: кнопка появляется, только когда страница ответила `ready`. Блок для поля ввода —
  `pickedPrompt()`; в `main.tsx` он дописывается к черновику.

**Проверка.**

- unit: `main/preview-bridge/inspector.test.ts` (jsdom: подсветка, клик, точный селектор находит тот же элемент,
  Esc, чужие сообщения игнорируются), `design/preview-server.test.ts` (вставка только в HTML, тег в начале
  `<head>`, без опции скрипта нет), `lib/preview-bridge.test.ts`, `CodePreviewPanel.test.tsx` (кнопка только после
  `ready` с нашего адреса и из нашей рамки; выбор → текст в поле; Esc).
- e2e: `e2e/features-pick.spec.ts` — агент пишет страницу, превью, «Выбрать на странице», клик по кнопке
  «Записаться» → в поле точное место, селектор из блока находит ту же кнопку, текст доходит до модели.
  Скриншоты: `features-pick-1-before.png`, `features-pick-2-hover.png`, `features-pick-3-after.png`.

**Не сделано.** Поиск `файл:строка` по проекту (п. 3 в §1.5, «по желанию»): агент и так находит место по
селектору и коду. Серверы агента (`127.0.0.1:<порт>`) без прокси инспектор не получают.

## 2. «На странице ошибка → Починить» (§1.2)

**Как устроено.**

  ошибки первых скриптов страницы.

- `lib/preview-bridge.ts`: `addPageError` (до 10 разных), `pageErrorLine`, `pageErrorsPrompt`.
- `CodePreviewPanel.tsx`: плашка; «Починить» → `onSend` → `sendPrompt` в `main.tsx`, тем же путём, что
  «Повторить». «Обновить» и новая страница начинают с чистого листа.

## Доп. Инспектор v2: общий формат выбора, файл и строка (research 20 §1)

**Что видит человек.** После «Выбрать на странице» в блоке появилась строка «Файл: index.html, строка 8», а если
таких элементов на странице несколько — «Таких на странице 3, выбран 2-й». Для элемента, который создал скрипт:
«…(элемент создал скрипт, это ближайший родитель)». Фрагмент кода короче и без наших пометок.

**Формат события** — `PreviewPick` в `packages/contracts/src/features.ts`, один для «Кода» и «Дизайна»:
`{selector, path, tag, text, outerHTMLShort, nth, of, rect, page, file?, line?, col?, exact?}`.

**Как устроено.**

- `main/preview-bridge/source-tags.ts`: parse5 (MIT, прямая зависимость 8.0.1, раньше был только через jsdom) с
  `sourceCodeLocationInfo`. В ответе сервера превью каждый элемент, написанный в файле, получает
  `data-pl="файл:строка:колонка"`. `<script>` и `<style>` не размечаются, чтобы не сдвигать колонки в ошибках
  встроенных скриптов. Файл на диске не меняется. Опция `tagSource` у `startPreviewServer`; «Код» её включает.
  Кодировка: UTF-8 остаётся UTF-8, остальное байт в байт.
- `inspector.js`: `outerHTMLShort` (атрибуты до 40 символов, не больше 6, текст до 60, ~200 всего; идея react-grab),

## Этап 2 · «Бот работает · Остановить · Журнал» (research/19 §1.10)

**Что видит человек.** В конце чата, пока фоновый процесс агента работает, — строка: зелёная точка, «Бот

показывает последние 200 строк, обновляется раз в 2 секунды и держит внизу новые строки, если человек не
листает вверх. После «Остановить» — «остановлен». Если процесс запустил не этот хост — «…остановить его здесь
нельзя». Процесс, который ещё работает, виден и при повторном открытии чата.

**Как устроено.** Без новой IPC в хосте и без правок харнесса.

- Список — из результатов инструментов этого чата: `bash_background` (`details {id, pid, logPath, ports}`) и
  серверная команда `bash`, которую харнесс перенёс в реестр (`details.prsloyServer` + `servers`).
  `lib/agent-processes.ts`: разбор, человеческое имя, «сколько работает».
- `main/features/processes.ts`, IPC с `assertTrustedSender`:
  - `proc-status` — жив ли pid (до 50);
  - `proc-log` — хвост журнала, через `scrubSecrets`. Читаются только журналы харнесса:
    `<tmp>/prsloy-harness/bg-<pid хоста>-<…>/bg<N>.log`;
  - `proc-stop` — останавливает так же, как `process stop` харнесса: дерево процессов (группа на POSIX,
    `taskkill /T /F` на Windows), сначала TERM, через 2 с KILL. Перед этим проверяет, что процесс наш: pid хоста
    из пути журнала, родитель хоста — этот main, родитель процесса — этот хост (`ps` / `Get-CimInstance`).
    Чужой pid остановить нельзя. Реестр харнесса сам видит выход процесса (событие `exit` своего потомка).
- `components/AgentProcesses.tsx` в `SessionTimelineContent.tsx` после «Что дальше». `main.tsx` не тронут.

**Ограничения.** Харнесс гасит фон на `session_shutdown`, поэтому сейчас процесс не переживает закрытие чата.
Если дорожка harness решит оставлять ботов жить (вопрос владельцу в §1.10 п. 4), строка покажет их при
открытии — она смотрит, жив ли pid. После перезапуска хоста «Остановить» для старых процессов честно откажет:
родитель уже не наш хост.

## Этап 3a · Имена папок и архивов по правилам Windows

`main/features/safe-name.ts` — одна функция для имени новой папки рецепта (`uniqueFolder`) и имени архива
(`zipName`):

- зарезервированные имена устройств — CON, PRN, AUX, NUL, COM1–9, LPT1–9 (и `¹²³`), в любом регистре и с
  любым расширением (`nul.txt` — тоже NUL) — получают `_` в начале;
- точки и пробелы по краям срезаются: Windows сама срезает их в конце, и «Сайт.» оказался бы чужой папкой
  «Сайт»;
- «.», «..», пустое имя и имя из одних запрещённых символов дают запасное «Проект» (у архива — `project`);
- символы `\ / : * ? " < > |` и управляющие заменяются пробелом (в архиве — `-`), повторы схлопываются;
- не длиннее 80 знаков. Длина считается по буквам (`Intl.Segmenter`: эмодзи и «й» — по одному), после обрезки
  снова срезаются точки и пробелы. Номер «Бот 12» вмещается в те же 80.

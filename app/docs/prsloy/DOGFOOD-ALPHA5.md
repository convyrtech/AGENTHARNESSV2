# Разработка через alpha 5

Решение владельца от 2026-11-09: реальные задачи памяти и оркестратора выполняет
агент внутри выпущенной alpha 5; внешний ведущий проверяет результат и фиксирует
расходы, ошибки и собственные вмешательства. Одна активная задача на шаг.

## Первый шаг — #73, проверка границ памяти

- Ветка `work/73-alpha5-dogfood` от `f4ffd32`.
- Исправление карточек уже в main: `b38d546` эквивалентно `e21f4c3` из старой ветки;
  `git cherry origin/main origin/work/memory-project-73` показывает `-`.
- Alpha 5 добавляет недостающий Electron-тест A → B → A в существующие тесты памяти.
- Приёмка: память A отсутствует в B, личная память доступна обоим проектам, при
  возврате в A его записи доступны снова; тест использует реальный preload/runtime,
  ответы модели внутри регрессионного теста имитируются явно.
- Ведущий отдельно запускает тест, проверяет diff, получает независимое ревью,
  запускает обязательные проверки и CI перед слиянием. Самоотчёт модели не является
  доказательством. Цена включает незавершённые и повторные платные вызовы.

При прогоне найден отдельный дефект #113: старый процесс проекта сохранялся под
путём следующего проекта. Возврат A → B → A поднимал процесс исходной папки.
Это не повтор прежнего исправления карточек #73. Область работы расширена только
на порядок переключения cwd и политику выбора сохранённого процесса; извлечение
памяти, разрешения и отмена не меняются.

Первые два прогона не завершились автономно: MiniMax остановлен ограничением
размера запроса нашего прокси; Kimi написала исходный тест, но не проверила его
и достигла лимита вызовов. Ведущий исправил окружение и сам тест: реальные
проектные пути, открытие через UI, новый чат, ожидание нового запроса, панель
памяти. Это сопровождённая разработка, а не доказательство самостоятельности
моделей. Исправление воспроизведённого дефекта дано MiniMax отдельной короткой
задачей с уже проверенной командой теста. За 12 вызовов MiniMax продолжил чтение,
не изменил код и не дал итогового ответа. Ведущий сам добавил две падающие
регрессии, исправил порядок переключения и сделал фактический cwd процесса
источником истины при сохранении и возврате. Эту часть нельзя приписывать альфе.

Новая сквозная проверка использует заранее записанные данные. Она доказывает
изоляцию чтения и передачи памяти модели, но не автоматическое извлечение или
создание карточек инструментом memory. Поэтому #73 не закрывается целиком.

Перед следующей платной задачей: проверить свободное место, доступность команд,
версию менеджера пакетов и запуск нужного теста в окружении исполнителя. При
неработающей команде — точная ошибка и остановка поиска инструментов. Не искать
ключи/пакеты по всему компьютеру и не устанавливать зависимости без необходимости.

## Следующий шаг — #103, один цикл делегирования

Ведущий формулирует ограниченное задание; исполнитель работает с отдельным контекстом;
другая модель проверяет фактический diff и результаты проверок; ведущий сообщает итог.
Подробные трассы хранятся отдельно, короткий результат различает заявления модели и
подтверждённые средой факты. Сначала последовательный цикл, затем сравнение с одним
агентом на одинаковой задаче. Параллельность и новые модели не включаем по впечатлению.

Первый прототип — один последовательный исполнитель, затем обязательное ревью
моделью другого семейства по фактическому финальному diff. Сначала за флагом.
Используем публичный Pi SDK; не расширяем ручной цикл `explore` инструментами
записи, обходящими обычные разрешения приложения.

- Новый контекст ребёнка: только его задание, выбранные файлы проекта и явные
  правила роли. Общие skills, extensions, настройки и переписка ведущего не
  наследуются. Повторное делегирование ребёнком выключено.
- Доступ к моделям через существующий runtime, без копирования ключей в файлы
  или контекст. Права ребёнка создаются заново; подтверждения доступны человеку.
- Общий лимит расходов исполнителя и ревьюера, с резервом для ревью. Stop отменяет
  запросы, команды и ожидающие диалоги; завершение процессов нужно дождаться.
- Результат содержит статус, короткий итог, изменённые пути, реальные exit codes,
  хеш проверенного diff, модель/вердикт ревьюера, расходы и ссылку на полную трассу.
  Заявление модели отделено от фактов среды. Нет ревью или diff изменён после него
  — результат «не проверено».
- Прямой `session.executeBash` в установленном SDK обходит `tool_call` hooks.
  Проверяющую команду нельзя запускать этим способом без общего preflight прав,
  обработки отмены и проверки настоящего exitCode/cancelled.
- После перезапуска незавершённая задача отмечается прерванной; действия с
  неизвестным результатом не воспроизводятся автоматически.

Приёмка прототипа: реальный SDK с фейковым шлюзом, запись файла, ненулевой exit
code, запрет команды, Stop, отсутствие общих ресурсов, недоступность ревьюера,
изменение diff после ревью и общий бюджет. Затем одинаковая небольшая реальная
задача через приложение: один агент / исполнитель / исполнитель с ревью.

Готовые идеи для контракта: [OMP task](https://github.com/can1357/oh-my-pi/blob/main/docs/tools/task.md)
разделяет короткий типизированный результат и полный журнал;
[manager orchestration](https://developers.openai.com/api/docs/guides/agents/orchestration)
оставляет принятие результата ведущему. Это основания дизайна, а не доказательство
улучшения качества PRSLOY. Сторонний код пока не переносился.

Память пользователя, память проекта и проверенные общие улучшения — разные области.
Глобальное изменение harness не публикуется автоматически из личной памяти.

## Актуальное окружение

Windows и опубликованный PRSLOY.exe запускаются локально. У агента приложения отдельный
профиль без общих пользовательских skills; проектные AGENTS.md доступны как контекст
разработки. Ключ шлюза держит внешний прокси; расходы берутся из журнала PRSLOY.
Старое CONTEXT.md с утверждениями о невозможности локального Windows-запуска и
отсутствии живого доступа не описывает этот стенд.

# Computer use #104: сравнение реализации

## Текущий контракт после исправлений, 2 ноября 2026

| Возможность   | Что дают Munim, Cua и Pi                                                          | Что добавляет PRSLOY и зачем                                                                                                                                                                                                        |
| ------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Подключение   | Pi запускает MCP и передаёт инструменты модели; драйверы реализуют действия.      | Opt-in, отдельный управляемый MCP и обёртки скрывают сырые вызовы от модели; прямой запуск harness без durable gate запрещает действия.                                                                                             |
| Граница окна  | Cua принимает PID и HWND; Munim наблюдает приложение по PID.                      | Cua проверяет целевой HWND; Munim требует один наблюдаемый window и привязывается к PID. Это не гарантия ОС: состояние процесса может измениться, shell остаётся отдельным каналом.                                                 |
| Свежесть      | Cua выдаёт токены снимка; короткие ID Munim могут повторяться.                    | Для Munim создаются непрозрачные токены поколения, для Cua проверяется текущий снимок; старый токен отклоняется до вызова backend. Повтор того же raw ID проверен отдельно в unit/Pi fixture.                                       |
| Stop и аварии | Pi передаёт сигнал отмены, но действие внешнего процесса может завершиться позже. | Общий SQLite-журнал записывает действие до dispatch, блокирует повтор при неизвестном результате и требует решения владельца. Поздние чтения Cua после Stop, включая image, отбрасываются. Stop не отменяет уже случившийся эффект. |
| Изображения   | Драйвер возвращает MCP image, Pi может передать image модели.                     | Сохранение image проверено через локальный scripted gateway в packaged-тестах. Живые модельные тесты v10 не отправляли изображения и не подтверждают реальное зрение модели или привязку screenshot Munim к HWND.                   |
| Совместимость | Старые процессы могли работать без общего журнала.                                | Текущие процессы разделяют durable gate; совместная работа со старым Munim-процессом не защищена и требует отдельного решения перед выпуском.                                                                                       |

Packaged v10 проверен на Windows с настоящим Munim и живой моделью, а также отдельно с Cua и живой моделью; подробные границы и результаты — в `COMPUTER-USE-104-PLAN.md`. Следующая таблица историческая и описывает исходный diff до этой интеграции.

Исходная таблица сравнивает незакоммиченный diff от `43841f6`, Munim 0.9.0 и Pi SDK. Позднее Cua 0.38.0 добавлен как экспериментальный opt-in backend и проверен в packaged Windows с mock-моделью, а также отдельно с живой моделью на синтетическом окне без передачи изображения. Cua не устанавливается и не распространяется вместе с PRSLOY. Packaged live E2E с Munim позже прошёл отдельно; это другой запуск и он не проверяет передачу изображения модели.

| Возможность     | Что уже делают компоненты                                                                                                                       | Зачем код PRSLOY / решение                                                                                                                                                                                                                                                                 |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Подключение     | Pi `createMcpExtension` запускает MCP и передаёт его инструменты агенту.                                                                        | Указать изолированный agentDir, включать только явный opt-in и только Munim; скрыть непроверенные инструменты через `toolExposure`. Не включать built-in MCP глобально.                                                                                                                    |
| Окна и действия | Munim предоставляет `list_apps`, `get_app_state`, element-ID операции и `return_state`; PID задаётся при чтении, не в каждом действии.          | Guard связывает PID с полученным списком, допускает только ограниченный набор действий по элементам и требует новое чтение после действия. Это не ОС-песочница и не гарантия, что пользовательский процесс содержит только одно окно.                                                      |
| Свежесть        | Munim IDs принадлежат последнему прочитанному состоянию и могут переиспользоваться. Cua документирует `element_token` с идентификатором снимка. | Guard инвалидирует снимок до действия и не считает ошибку наблюдением. Если Munim повторно выдаст тот же короткий ID другому элементу, guard сам не может доказать, из какого снимка модель взяла ID. Cua стоит отдельно сравнить на одинаковом Windows fixture; здесь замены backend нет. |
| Stop            | Pi передаёт `AbortSignal` MCP-вызову и сообщает `agent_settled.aborted`; Munim выполняет действие во внешнем процессе.                          | Не изобретать вторую отмену; блокировать следующие действия после отмены, не повторять автоматически незавершённые операции. Сигнал отмены не доказывает, что уже начатое действие не произошло.                                                                                           |
| Изображение     | Munim возвращает MCP image, Pi конвертирует его в содержимое для модели с поддержкой изображений.                                               | Не преобразовывать image в текст; проверить передачу от настоящего screenshot до запроса модели в packaged E2E. Отдельный canary шлюза не доказывает этот путь.                                                                                                                            |

Таблица выше отражает исходную реализацию Munim, а не позднее добавленные Cua-обёртки. PID в ней извлекается из текстового ответа Munim. Этот формат нельзя считать надёжной защитной границей против злонамеренных окон или подменённого вывода backend. Для Cua используются токены снимка самого драйвера; общий профильный SQLite-журнал подключён к действиям Cua и проверен с аварией хоста на packaged Windows fixture. Подтверждённый повторным чтением ввод не требует решения владельца; клик и неопределённые результаты блокируют следующие действия до решения владельца. Ограничения Cua-пути не являются песочницей: обычные инструменты, например shell, остаются отдельным каналом действий.

Источники: установленный Pi SDK `dist/extensions/mcp/tools.js`, `dist/core/extensions/types.d.ts`; фактический `tools/list` Munim 0.9.0; [Munim](https://github.com/munimtechnologies/munim-computer-use); [Cua Driver: устройство](https://github.com/trycua/cua/blob/main/docs/content/docs/cua-driver/concepts/how-cua-driver-works.mdx) и [работа с токенами снимков](https://github.com/trycua/cua/blob/main/libs/cua-driver/rust/Skills/cua-driver/SKILL.md). Данные main в сторонних репозиториях могут измениться; не считать их проверкой установленного бинарника Cua.

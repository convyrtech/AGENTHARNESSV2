# @prsloy/harness

Расширение Pi 1.4, которое грузится в каждую сессию агента PRSLOY Desktop. Оно делает дешёвые модели
(DeepSeek V4.1 Flash, Kimi K3.1) надёжнее: всё в коде, ничего не держится только на промпте. Каждая
практика уже доказана в наших досье или экспериментах (`PLAN-alpha.md` §3); новых не придумывали.

## Подключение

```ts
import { createPrsloyHarness } from "@prsloy/harness";

new DefaultResourceLoader({
  cwd,
  agentDir,
  extensionFactories: [createPrsloyHarness({ profile: "code" })],
});
```

Ещё два способа, оба проверены интеграционным тестом:

- путь к файлу: `additionalExtensionPaths: [".../packages/prsloy-harness/src/index.ts"]` (так грузит
  `extensionPaths` дорожки ядра). Профиль тогда берётся из `PRSLOY_PROFILE` (`code` по умолчанию);
- каталог пакета: в `package.json` есть `pi.extensions`.

`register(pi)` — точка входа с настройками по умолчанию. Настройки (`HarnessOptions`) описаны в
`src/options.ts`; любую практику можно выключить через `disable`.

## Почему серверы через `&` переписываются, а не отслеживаются

Процесс из `(cmd &)` после выхода оболочки переподчиняется init: надёжно найти его потом можно только по
порту или командной строке, а это гадание (чужие процессы, тот же порт у другого сервера, разный `ps` на Linux,
macOS и Git Bash). Если запустить задачу самим через реестр, PID, порт и лог известны с первой секунды, сервер
закрывается с сессией и при падении хоста, а `pkill` по нему превращается в точную остановку. Переписывается
только то, что разобрано уверенно: кавычки и скобки сходятся, `cd` перед задачей без переменных, задача похожа
на сервер (`looksLikeServer` или `node server.js`, `python app.py` и т. п.). Остальное — `sleep 1 & sleep 2 &
wait`, сборки, циклы — выполняется как написано.

Почему `pkill -f` убивал сам себя: Pi запускает команду как `bash -c "<команда>"`, и шаблон из команды есть
в командной строке этого bash. Pi ставит bash в отдельную группу процессов, поэтому безопасная замена
(`__prsloy_pkill`) пропускает процессы своей группы: сервер, запущенный прошлым вызовом, — в чужой группе
и будет убит, а свой shell — нет. На Windows групп нет, поэтому там `pkill -f` блокируется с подсказкой
`process action=stop port=…`.

## Порядок обработчиков

`tool_call`: бюджет → петли → таймаут bash (первый блок останавливает цепочку, поэтому сервер не запустится,
если бюджет исчерпан). `tool_result` идёт цепочкой в порядке установки: петли → таймаут → вывод → правки → проверка синтаксиса →
предупреждение бюджета → секреты. Пути файлов разрешаются как в Pi (`src/paths.ts`: `@`, `~`, `/c/…` Git Bash на Windows).

## Проверка

```sh
cd app/packages/prsloy-harness && pnpm test
```

Модульные тесты используют мок `ExtensionAPI` с семантикой `ExtensionRunner` Pi 1.4 (`test/mock-pi.ts`).
`test/integration.test.ts` поднимает настоящую сессию `createAgentSession` против локального мок-шлюза
(`test/scripted-openai-server.ts`) и показывает срабатывание детектора петель, таймаута bash, бюджета,
псевдовызова, проверки синтаксиса, чистки секретов и раздела промпта.

# Motion Contract — лендинг PRSLOY API

> Заполнено ДО кода, 2026-10-23. `tools/motion_probe.py` сверяет реализацию с этим файлом.
> Источники: разбор эталона warp.dev (`01-teardown.md`: CSS-переходы 300 мс `cubic-bezier(0.4, 0, 0.2, 1)`, пульс 1,8 с),
> скилл LottieFiles/motion-design-skill (MIT): характер «Premium» + материал «жёсткий металл» (×1,2 к длительности,
> без перелёта), правило 1/3, одна фирменная кривая на 80% движений. Непроверенное помечено «предположение».

## 1. Trigger
- `load` — живая схема «fig. 1» на первом экране: бесконечный цикл, пауза вне экрана и на скрытой вкладке.
- `in-view` — рамки рисунков, изометрические сцены, шаги до ключа, шкала баланса: один раз при 25% элемента в вьюпорте.
- `click` — вкладки подключения (Cursor / Claude Code / Cline / OpenAI SDK).
- Текст, заголовки и кнопки НЕ анимируются на входе: видны и нажимаются с 0 мс.

## 2. Объекты (что движется независимо)
- Слой A, `fig1-packet`: квадрат-пакет запроса 10×10 px, едет по линиям схемы «программа → шлюз PRSLOY → модель → обратно».
- Слой B, `fig1-node`: индикаторы узлов схемы (программы, шлюз, модели): смена состояния и пульс.
- Слой C, `fig1-odometer`: счётчик «списано ₽» в шлюзе, цифры прокручиваются по разрядам.
- Слой D, `frame-draw`: рамка рисунка «чертится» слева направо при входе в экран (clip-path на рамке, содержимое видно сразу).
- Слой E, `iso-draw`: изометрическая сцена (турникет, терминал оплаты, станок для ключа) прорисовывается линией.
- Слой F, `steps-rule`: линия между шагами «Регистрация → Пополнение → Ключ» вытягивается.
- Слой G, `tab-indicator` + `tab-panel`: подчёркивание активной вкладки и смена кода.
- Слой H, `gauge-fill`: штриховка шкалы-пробирки баланса поднимается до уровня.
- Слой I, `journal-tick`: журнал списаний сдвигается на одну строку, когда приходит новая запись.

## 4. Easing / spring (точные значения)
- Всё, кроме вкладок: `cubic-bezier(0.4, 0, 0.2, 1)` (фирменная, как у эталона).
- Подчёркивание вкладки: `cubic-bezier(0.2, 0, 0, 1)` (быстрый решительный отклик).
- Пульс: `linear`, бесконечно.
- Пружин нет: жёсткий металл, перелёт 0%.

## 5. Path
- Пакет едет по ломаной из прямых отрезков вдоль линий схемы. Каждый отрезок короче трети ширины экрана (шлюз посередине) — правило 1/3 по расстоянию. Точки ломаной берутся из координат узлов SVG при сборке, не на глаз.

## 6. Texture
- Механическая, точная, без отскоков: как самописец или табельные часы. Цифры счётчика «щёлкают» по разрядам.

## 7. Interrupt-поведение
- Быстрая прокрутка назад: начерченное остаётся начерченным, обратной анимации нет.
- Клик по вкладке во время перехода: мгновенный снап к новой вкладке.
- Схема ушла из экрана или вкладка скрыта (`visibilitychange`): цикл на паузе, при возврате продолжает со следующего маршрута.
- Возврат «назад» (`performance.getEntriesByType('navigation')[0].type === 'back_forward'`): интро нет, всё в финальном состоянии.

## 8. Перф-бюджет (мобилка = приоритет)
- Target FPS (mid-mobile): `>= 55`
- Frame time: `< 18ms`
- Layout-shift во время анимации: `0` (места под код, журнал и счётчик зарезервированы)
- Макс. одновременно анимируемых слоёв: `3` (правило 1/3: в схеме одновременно двигаются пакет и один узел)
- Свойства: только `transform` и `opacity`, плюс `clip-path` рамки и `stroke-dashoffset` сцен. Последние два рисуются заново (не композитор), поэтому одновременно не больше одной рамки и одной сцены — `предположение`, что это держит 55 кадров на среднем телефоне, проверить `motion_probe.py`.
- Вспышки: нет; смена цвета узла не чаще 1 раза в 1,2 с, вспышек на большой площади 0.

## 9. reduced-motion
- `prefers-reduced-motion: reduce`: статичный финальный кадр. Схема показывает один завершённый маршрут (пакет у модели, путь акцентом), счётчик с итоговым значением, рамки начерчены, сцены прорисованы, шкала заполнена, журнал неподвижен. Бесконечных анимаций нет, содержимое не прячется.
